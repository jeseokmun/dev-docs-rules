# 템플릿 — DEV-66 장애공지 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「장애 중 사람에게 보내는 공지」. 파일 하나 = 공지 하나. Atlassian Statuspage의 조사 중·원인 확인·지켜보는 중·해결에 해당한다.
> **경로:** `{docs_root}/DEV-66-장애공지/DEV-66-{슬러그}.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 지금 사람에게 무슨 말을 보내나 | ＊ 본문 | 증상·원인·조치의 내부 기록은 DEV-62 |
| 공지 상태가 어디인가 | ＊ 상태 | 운영자가 로그를 보고 되돌리는 절차는 DEV-60·DEV-80 |
| 이번 공지에서 단정하지 않는 것 | ＊ 말하지 않음 | 화면 문구의 상시 키는 DEV-28 |
| 당장 피할 방법이 있나 | ○ 우회 | 저장본을 되돌리는 절차는 DEV-60. 스키마 이전의 롤백은 DEV-38 |

필수 프로필에 이 코드는 없다. 보낼 공지가 없으면 `상태`는 `공지 없음`이다. 없는 장애를 만들어 채우지 않는다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 절이 lint를 통과. `공지 없음`도 통과한다 |
| 리뷰 | 본문이 누구에게, 다음에 언제 알릴지, 무엇을 말하지 않는지를 빠뜨리지 않았는지 본다 |
| active | 보낸 공지와 이 파일의 본문이 같다 |
| deprecated | 다음 공지가 이 파일을 대체하면 deprecated로 두고 ○ 관련에 새 파일 경로를 적는다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다.

## 사람 검토

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 상태 | 상태는 `조사 중`, `원인 확인`, `지켜보는 중`, `해결`, `공지 없음`만이다. 열 `상태`·`누구에게`·`다음에 알릴 때` |
| ＊ 상태 | 누구에게는 영향 받은 역할만 적는다. 영향 받은 사람 수를 모르면 지어 넣지 않는다 |
| ＊ 상태 | 다음에 알릴 때는 다음 알림의 시점만 적는다. 분 단위를 모르면 그 사실을 적는다 |
| ＊ 본문 | 지금 보내는 말. `공지 없음`이면 보내지 않는 이유를 적는다. |
| ＊ 말하지 않음 | 열 `내용`·`이유`. 확인하지 않은 원인, 복구 시각, 영향 범위를 단정하지 않는다. |
| ○ 우회 | 열 `방법`·`한계`. 우회가 없으면 절을 둔다. 없는 방법을 만들지 않는다. |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-66.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-66-장애공지/DEV-66-{슬러그}.md` |
| 위치 | 다건. 폴더 밖 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-66` |
| ＊ 본문 | 문자열. 자리표시가 아닌 1자 이상. `공지 없음`이면 보내지 않는 이유다 |
| ＊ 말하지 않음 | 열 `내용`, `이유`. 최소 1행 |
| ＊ 상태 | `상태`가 다섯 단어 밖이면 `COLUMN_VALUE` |

미결 열은 `ID`·`미결`·`다음에 할 일`이다. lint는 그 열 이름을 보지 않는다.

## 작성 규칙

- 한 파일은 한 공지다. 내부 사례와 이 파일을 한 문서에 섞지 않는다.
- 채널 이름은 HC-CHANNEL. 이름을 만들지 않는다. 수신자 수를 모르면 지어 넣지 않는다.
- `공지 없음`은 장애를 숨기는 말이 아니다. 보낼 사건이 없을 때의 상태다.
