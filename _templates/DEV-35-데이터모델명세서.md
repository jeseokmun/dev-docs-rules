# 템플릿 — DEV-35 데이터모델명세서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-35-데이터모델명세서/DEV-35-{슬러그}.md` (다건)
> **용도:** 헌법 §5. ER, 필드, 제약. 스키마에 그림 절은 없다. 관계를 그림으로 보여줄 때는 헌법 §1.7–§1.8대로 Mermaid를 쓰고 표시 라벨은 DOC-CONFIG language를 따른다. lint는 그 그림을 검사하지 않는다.
> **가독성:** 표 우선. 산문은 요약 1–3문장 (헌법 §1.11). 한 파일은 한 모델 묶음이다 (헌법 §1.6).

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 헌법 §1.9 |
| ○ | 권장 절. 제품 문서에서 빼도 필수 검사에는 없다 |

## 문서 성숙도

| 단계 | 이 유형에서 |
|---|---|
| draft | ＊ 개요, ＊ 모델, ＊ 관계, ＊ 금지가 lint를 통과하면 된다 |
| 모르는 값 | 확인하지 않은 필드 타입이나 기수를 넣지 않는다. 칸은 `미결`, 미결 표에는 다음에 볼 스키마나 코드 |
| 리뷰 | 보강 요청은 제약 칸이 `미결`인 필드의 목록이다 |
| active | 핵심 미결이 닫히고, 필드와 기수를 저장 구조와 다시 맞춰 볼 수 있을 때 |
| 어긋남 | 저장 구조가 바뀌면 이 파일을 고치거나 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 개요 | 이 모델이 어디에 저장되는지 한 줄. 장소를 모르면 `미결`과 다음에 확인할 일 |
| ＊ 모델 | 엔티티, 필드, 형, 제약이 한 행에 하나. 최소 1행. 형과 제약은 확인된 것만. 날짜 필드의 형은 달력 날짜만 적는다. 하루를 자르는 시각은 그 칸에 다시 쓰지 않고 HC-MIDNIGHT를 가리킨다. RFC 3339(G. Klyne, C. Newman, 2002)는 full-date와 full-time을 나눈다 |
| ＊ 관계 | 출발, 도착, 기수, 설명. 기수는 확인된 값만. `1:N`처럼 보이려고 추정 기수를 넣지 않는다 |
| ＊ 금지 | 하지 말 것과 이유. 첫째 행은 헌법 §1.5의 개인 실데이터 샘플 금지라 남긴다. 제품 금지가 더 있으면 행을 더하고, 없으면 `…` 행을 지운다 |
| ○ 수명·삭제 | 엔티티, 보관, 삭제. 같이 지워지는 대상을 모르면 그 절의 자리표시 행은 두지 않는다. 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 시작한다 |
| ○ 관련 문서 | 코드와 실제 경로. 구조는 DEV-30, 이전은 DEV-38일 수 있다. 없는 파일은 적지 않는다 |

그림을 넣을 위치는 ＊ 관계 절의 표 아래이다. 확인하지 않은 엔티티로 상자를 채우지 않는다.

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준은 `_schemas/DEV-35.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다. 이 스키마의 `rules`에는 Mermaid 항목이 없다.

| 항목 | 기준 |
|---|---|
| 역할 | light·full 필수 목록에 없다. 없어도 프로필 검사는 통과한다. 파일이 있으면 본문을 검사한다 |
| 경로 | `{docs_root}/DEV-35-데이터모델명세서/DEV-35-{슬러그}.md` |
| 위치 | 다건. 루트 단독 파일은 DOC_PATH |
| 제목 | `#` 줄에 `DEV-35`가 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-35. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸의 `…`와 헤더의 `YYYY-MM-DD`는 실패한다. `없음`과 `미결`은 자리표시가 아니다 |
| 빈 칸 | 이 유형의 표에는 `비고`와 `□` 헤더가 없다. 빈 칸은 EMPTY_CELL |
| 선택 절 | 열 이름을 검사하지 않는다. 복사용 수명 열은 엔티티·보관·삭제, 관련 문서는 코드·경로 |
| 미결 | 스키마 열은 ID·미결·다음에 할 일. 열 이름은 검사하지 않는다. 빈칸은 EMPTY_CELL |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 개요 | string, min 1 | 자리표시가 아닌 1자 이상 |
| ＊ 모델 | table. 엔티티, 필드, 형, 제약. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 관계 | table. 출발, 도착, 기수, 설명. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |

## 복사한 뒤

개요와 모델·관계의 `…`는 바꾸기 전에 lint가 실패한다. 필드가 둘 이상이면 모델 행을 더한다. 관계가 없으면 출발·도착·기수·설명에 `없음`과 이유를 적는다. 빈 칸으로 두지 않는다. 금지의 첫째 행은 패키지 규칙이라 남기고, 둘째 행은 제품 금지를 적거나 지운다. 수명·삭제를 모르면 그 절의 자리표시 행은 두지 않는다. 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 시작한다. 관련 문서의 파일이 없으면 그 행을 만들지 않는다. DEV-38 행은 이전 명세가 있을 때만 추가한다.
