# 템플릿 — DEV-80 배포및장애절차서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「배포·장애 절차」. 파일 하나 = 배포 대상 하나.
> **경로:** `{docs_root}/DEV-80-배포및장애절차서/DEV-80-{슬러그}.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 어느 환경에 무엇을 올리나 | ＊ 환경 | 반복해서 하는 일반 운영 절차는 DEV-60 |
| 누가 이 배포를 승인하나 | ○ 승인 | 실행하는 사람은 ＊ 배포 단계의 행위자다. 승인 역할의 사람 명단은 헌법 §0.4대로 비어 있다. 이름을 짓지 않는다 |
| 누가 어떤 순서로 올리고 무엇을 보면 성공인가 | ＊ 배포 단계 | 스토어 문구와 제출 기록은 DEV-85 |
| 언제 되돌리고, 데이터는 돌아오나 | ＊ 롤백 | 스키마 이전의 절차는 DEV-38. 배포가 이전을 포함하면 방법 칸에 그 DEV-38 경로를 적는다 |
| 장애의 첫 행동과 넘길 곳 | ○ 장애시 | 이미 끝난 사례의 원인 분석은 DEV-62 |

필수 프로필에 이 코드는 없다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 세 절이 lint를 통과. ＊ 배포 단계는 1행이면 기계는 통과한다 |
| 리뷰 | 검증 칸이 `헬스체크 성공 기준`처럼 채워야 할 자리만 가리키면 보강으로 돌려보낸다 |
| active | 배포를 쓰지 않은 사람이 검증 칸의 결과만으로 그 단계를 통과했는지 말한다. 롤백의 확인 칸은 데이터가 돌아오는지, 돌아오지 않는지를 말한다 |
| deprecated | 환경을 빼면 이 파일을 deprecated로 두고 대체 파일 경로를 ○ 장애시 또는 미결이 아닌 환경 표의 비고에 적는다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 환경 | 열 `환경`·`대상`·`비고`, 최소 1행. 환경은 이름, 대상은 올라가는 산출물, 비고는 그 환경만의 제약이다. 헤더가 정확히 `비고`라 빈 칸과 `…`는 lint를 통과한다. 사람 검토는 제약이 있는데 비고가 비면 돌려보낸다. |
| ○ 승인 | 열 `무엇`·`역할`·`사람`. 역할은 헌법의 `[개발론]`처럼 그 프로젝트가 정한 승인 역할 이름이다. 사람 칸은 명단이 비어 있으면 비어 있다고 적는다. 행위자 칸에 승인 역할을 적지 않는다 |
| ＊ 배포 단계 | 열 `순서`·`행위자`·`행동`·`검증`, 최소 1행. 검증은 그 단계의 성공을 보는 관측이다. 성공 조건을 모르면 `조건을 아직 정하지 않음`이라고 적고 미결에 정할 사람을 적는다. 행위자는 실행하는 사람이다 |
| ＊ 롤백 | 열 `조건`·`방법`·`확인`, 최소 1행. 조건은 되돌리는 계기, 방법은 하는 일, 확인은 돌아온 뒤 보는 결과다. 데이터를 되돌리지 못하면 확인 칸에 그 범위를 적는다. 보장하지 않는 복구를 보장한다고 쓰지 않는다. |
| ○ 장애시 | 열 `징후`·`초기 대응`·`에스컬레이션`. 수신자를 모르면 에스컬레이션에 `수신자 미정`이라고 적고 미결에 정할 행동을 적는다. 호출 제품 이름을 지어 넣지 않는다. |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-80.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-80-배포및장애절차서/DEV-80-{슬러그}.md` |
| 위치 | 다건. 폴더 밖 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-80`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-80`이 단어로 있다 |

| 필수 제목 | 열 순서 | 최소 행 |
|---|---|---|
| ＊ 환경 | 환경, 대상, 비고 | 1 |
| ＊ 배포 단계 | 순서, 행위자, 행동, 검증 | 1 |
| ＊ 롤백 | 조건, 방법, 확인 | 1 |

`비고`가 아닌 필수 칸의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. ○ 장애시의 `…`는 `FAKEFILL`이 아니고 빈 칸은 `EMPTY_CELL`이다. 미결 열은 `ID`·`미결`·`다음에 할 일`이다. 스키마 `rules`는 실행되지 않는다.

## 작성 규칙

- 헤더 범위는 이 배포 대상, 헤더 비범위는 일반 운영(DEV-60), 스토어 문구(DEV-85), 이전 절차의 전문(DEV-38)이다.
- 환경 표에서 `…`가 실패하지 않는 칸은 `비고`뿐이다. `환경`과 `대상`의 `…`는 `FAKEFILL`이다.
- 온콜 도구나 상태 페이지 이름을 이 양식이 정해 주지 않는다.
- 비밀 값과 개인정보 샘플은 명령 예시에 넣지 않는다.
