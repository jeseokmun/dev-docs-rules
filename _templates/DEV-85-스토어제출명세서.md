# 템플릿 — DEV-85 스토어제출명세서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「스토어 제출·심사 기록」. 파일 하나 = 제출 대상 하나.
> **경로:** `{docs_root}/DEV-85-스토어제출명세서/DEV-85-{슬러그}.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다. 이 패키지는 스크린샷 장수, 연령 등급, 스토어 정책 문장을 정해 두지 않는다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 스키마에 □ 절이 없다. 스크린샷·등급을 □ 제목으로 추가하지 않는다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 스토어, 패키지 이름, 버전 | ＊ 식별 | 빌드와 롤백 명령은 DEV-80 |
| 짧은 문구와 그 문구를 잠글지 | ＊ 짧은 설명 | 앱 안 UI 문구는 DEV-28 |
| 출시 전에 닫혀야 하는 문 | 적지 않는다 | DEV-86. 제출 여부와 문구는 이 문서 |
| 긴 문구를 확정했는지 | ○ 긴 설명 | 릴리즈가 사용자에게 보이는 변경은 DEV-90 |
| 스크린샷 장수와 연령 등급 | 알면 ＊ 식별의 추가 행. 모르면 미결 | 이 스키마에 그 열은 없다. `비강제`라고 적어 정책을 만들지 않는다 |

필수 프로필에 이 코드는 없다. 헌법 §3.3은 스토어가 있을 때 상황 권장으로 둔다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 두 절이 lint를 통과 |
| 리뷰 | 패키지 이름이나 잠금 여부를 모르면 `미정`을 문장으로 적고, 미결 `내용`에 `없는 사실:`과 `다음 행동:`을 적는다 |
| active | 짧은 설명의 문구가 제출할 문장이거나, 이번 버전이 제출하지 않으면 문구 칸에 `제출하지 않음`과 그 이유가 있다. 홍보 문장을 이 양식이 써 주지 않는다 |
| deprecated | 제출 대상이 바뀌면 새 파일을 만든다 |
| deprecated | 이 파일은 그 버전의 기록으로 남긴다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다. 헌법 §1 원칙 10의 스크린샷 비강제는 DEV-10 등 문서 스크린샷에 대한 말이며, 스토어 등록 스크린샷의 의무를 정하지 않는다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 식별 | 항목은 제출에 필요한 이름이다. 열 `항목`·`값`, 최소 1행. 패키지 또는 번들, 플랫폼, 버전처럼 행으로 나눈다. 두 스토어를 슬래시로 묶어 한 칸에 두지 않는다 |
| ＊ 식별 | 값은 그 항목의 값만 적는다. 값을 모르면 `패키지 이름 미정`처럼 무엇을 모르는지를 적는다 |
| ＊ 짧은 설명 | 언어는 그 문구의 언어다. 열 `언어`·`문구`·`잠금?`, 최소 1행 |
| ＊ 짧은 설명 | 문구는 제출할 문장만 적는다 |
| ＊ 짧은 설명 | 잠금?은 그 문장을 더 고칠지다. 헤더 `잠금?`에는 `□`가 없으므로 `…`는 `FAKEFILL`이다. 잠금을 정하지 않았으면 `잠금 여부 미정`이라고 적는다 |
| ○ 긴 설명 | 언어는 그 문구의 언어만 적는다. 열 `언어`·`상태`. `미결` 한 단어는 기계가 통과시키는 假채움이므로, 언어를 문장으로 적는다 |
| ○ 긴 설명 | 상태는 문구를 확정했는지만 적는다. 확정 여부를 언어 문장에 붙이지 않는다 |
| ○ 긴 설명 | 확정된 문구 전문을 이 열에 다 넣지 못할 때는 상태 칸에 문구가 있는 경로를 적는다 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-85.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-85-스토어제출명세서/DEV-85-{슬러그}.md` |
| 위치 | 다건. 폴더 밖 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-85`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-85`가 단어로 있다 |

| 필수 제목 | 열 순서 | 최소 행 |
|---|---|---|
| ＊ 식별 | 항목, 값 | 1 |
| ＊ 짧은 설명 | 언어, 문구, 잠금? | 1 |

필수 칸의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. 미결 스키마 열은 `ID`·`내용`뿐이다. 내용 칸은 `없는 사실:` 문장과 `다음 행동:` 문장이다. lint는 그 열 이름과 꼬리표를 보지 않는다. 스키마 `rules`는 실행되지 않는다. 선택 표의 `…`는 `FAKEFILL`이 아니고 빈 칸은 `EMPTY_CELL`이다.

심사 계정, 비밀번호, 토큰은 헌법 §1 원칙 5의 비밀이다. `SECRET_LIKE`에 걸리지 않아도 넣지 않는다.

## 작성 규칙

- 헤더 범위는 이번 제출의 스토어 메타, 헤더 비범위는 배포 명령(DEV-80), 릴리즈 노트(DEV-90), 심사 계정 비밀이다.
- 짧은 설명은 언어마다 한 행이다. 쓰지 않는 언어의 행을 `…`로 남겨 두지 않는다.
- 슬러그는 lint가 검사하지 않는다. 스토어와 버전을 파일명에 적어도 도구는 본문과 대조하지 않는다.
