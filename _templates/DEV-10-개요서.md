# 템플릿 — DEV-10 개요서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-10-개요서.md` (단건, 문서 루트)
> **용도:** 헌법 §5. 무엇·누구·경계·최소 실행.
> **가독성:** 표 우선. 산문은 요약 1–3문장 (헌법 §1.11). 스크린샷은 강제하지 않는다 (헌법 §1.10).

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 헌법 §1.9가 이 기호를 필수 칸에 쓴다 |
| ○ | 이 템플릿의 권장 절. 제품 문서에서 빼도 필수 검사에는 없다 |
| □ | 이 템플릿의 선택 칸. 헤더에 이 기호가 있으면 그 칸의 빈 값과 자리표시는 lint 예외 |

## 문서 성숙도

헌법 §1.5를 이 유형에 적용한다.

| 단계 | 이 유형에서 |
|---|---|
| draft | 아래 ＊ 절이 lint를 통과하면 된다. 이상형 미달은 draft 실패가 아니다 |
| 모르는 값 | 확인하지 않은 문장으로 필수 칸을 채우지 않는다. 그 칸에는 `미결`을 적고, 미결 표 내용에 다음에 할 일을 적는다. 필수 절을 지우거나 자리표시만 남기면 lint는 실패한다 |
| 리뷰 | 보강 요청은 다음에 채울 항목 목록으로 남긴다 |
| active | 핵심 미결이 닫히고, 적힌 실행과 검증을 다시 따라갈 수 있을 때 |
| 어긋남 | 코드나 사실이 문서를 이기면 문서를 고치거나 상태를 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다. 열 이름, 최소 행, 자리표시는 기계 검사에 있다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 한 줄 소개 | 누가, 무엇을, 어디에 두는지가 한 문장에 있다 |
| ＊ 누구를 위한가 | 실사용자와, 이 제품이 맞지 않는 비사용자가 각각 있다. 행 키는 사용자·비사용자뿐이다 |
| ＊ 핵심 기능 | 사용자가 하는 일을 동사로 적는다. 스키마 최소는 3행이고, 일이 더 있으면 행을 더한다 |
| ＊ 실행·설치 | 저장소에서 확인한 명령과 경로만 적는다. 허용 키는 개발·사용자·환경이다. 모르는 키는 행을 만들지 않고 미결에 둔다 |
| ＊ 시스템 경계 | 하지 않는 일과 그 이유를 한 행에 적는다. 최소 2행. 이유에는 왜 지금 제품 밖에 두는지를 적는다 |
| ○ 왜 필요한가 | 키 `문제`와 `접근`에 각각 하나씩 적는다. 열 헤더는 구분·내용이다 |
| ○ 성공·검증 | 성공해 보이는 상태와, 그 상태를 확인하는 절차를 한 행에 적는다 |
| ○ 관련 문서 | 본문이 기대는 문서의 코드와, 그 파일의 실제 경로를 적는다. 파일이 없으면 행을 넣지 않는다 |

이상형 힌트 명령은 `python _tools/ideal_check_min.py {docs_root} --summary-only`이다. draft 탈락 조건이 아니다. 확인하지 않은 URL이나 명령을 힌트에 맞추려고 넣지 않는다.

| 힌트 | `_tools/ideal_check_min.py`가 보는 것 |
|---|---|
| 실행 | `http://`, `https://`, `git@`. 또는 백틱 안의 npx, npm, pnpm, yarn, expo, flutter, dart, cargo, dotnet, python, python3, uv. 또는 백틱 밖에서 npx, npm, expo, flutter, dart 다음에 인자가 이어지는 줄. make만 있는 문장은 안 걸린다 |
| 성공 | 제목에 `성공` 또는 `검증`이 있다 |
| 관련 | 제목에 `관련`이 있고 본문에 DEV-20 또는 DEV-30이 있다 |
| SKIP | 동기 품질, 자동 테스트와 저장소의 연결, 일정, 플랫폼 범위 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준은 `_schemas/DEV-10.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다. 스키마 `rules` 이름은 별도 엔진으로 실행되지 않는다.

| 항목 | 기준 |
|---|---|
| 역할 | light의 필수 문서. full은 light를 포함하므로 역시 필수. 파일이 없으면 MISSING |
| 경로 | `{docs_root}/DEV-10-개요서.md` |
| 위치 | 단건. 다른 경로면 DOC_PATH |
| 제목 | `#`으로 시작하는 줄에 `DEV-10`이 단어로 있다 |
| 헤더 | 첫 H2 앞에 상태·코드·마지막 갱신·범위·비범위. 두 열 표 또는 `- **키:** 값`. 코드는 DEV-10. lint가 보는 날짜는 달력의 YYYY-MM-DD이다. DOC-CONFIG `timezone`은 사람이 그 날짜를 고를 때 쓰는 기준이다 |
| 상태 | 기본은 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록. `config()`는 `- **키:** 값`만 읽는다 |
| 중복 | 같은 H2가 두 번이면 DUPLICATE_SECTION |
| 자리표시 | 칸 전체가 빈 문자열, `—`, `–`, `-`, `…`, `...`, `TBD`, `TODO`, `tbd tbd`, `lorem ipsum`, `YYYY-MM-DD`, `{중괄호 한 조각}`이면 필수 절과 헤더에서 실패한다. 앞뒤 공백과 `` `_* ``를 벗긴 뒤 비교한다. `없음`과 `미결`은 그 목록에 없다 |
| 빈 칸 | 문서의 모든 표에서, 헤더가 `비고`가 아니고 `□`를 포함하지 않는 칸이 비어 있으면 EMPTY_CELL |
| 선택 절 | 없어도 통과한다. 있어도 열 이름과 자리표시는 검사하지 않는다. 선택 표의 빈 칸은 전역 EMPTY_CELL에 걸린다. 복사용 본문은 그래도 스키마 열을 쓴다 |
| 미결 | 스키마 열은 ID·내용. lint와 schema_sync는 이 열 이름을 비교하지 않는다. schema_sync는 템플릿에 제목 `미결`이 한 번 있는지만 본다. 헌법 §1.5.2는 미결에 빈칸과 다음에 할 일을 적으라고 한다. 빈칸은 EMPTY_CELL이므로, lint를 통과하는 적기는 칸에 `미결`을 두고 같은 행 내용에 다음에 할 일을 쓰는 것이다 |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 한 줄 소개 | string, min 1 | 자리표시가 아닌 1자 이상 |
| ＊ 누구를 위한가 | kv_rows. 열은 구분·내용. 키는 사용자·비사용자. min_rows 2 | 키가 둘 다 있어야 한다. 다른 키는 UNKNOWN_KEYS |
| ＊ 핵심 기능 | numbered_rows. 열 순서는 #, 사용자가 하는 일. min_rows 3 | 열 순서, 행 수, 빈 칸, 자리표시. 표로 검사한다 |
| ＊ 실행·설치 | kv_rows. 열은 구분·내용. 키는 개발·사용자·환경. min_rows 1 | 허용 키만. min_rows가 키 개수보다 작아 세 키가 모두 없어도 된다 |
| ＊ 시스템 경계 | table. 열 순서는 하지 않는 것, 이유. min_rows 2 | 열 순서, 행 수, 빈 칸, 자리표시 |

사람 검토가 이 표보다 엄하면, 그 차이는 active로 올리기 전의 편집 기준이다.

생성기는 DEV-10과 DEV-30만 있다. `render_doc.py`는 비어 있는 필수 값을 본문에 넣지 않고 미결에 `{절 이름} 미기입`을 추가한다. 그 파일에 필수 H2가 없으면 lint는 실패한다. 값 JSON은 임시이고 저장 원본은 마크다운이다. 초안은 `docs_draft_cli.py`, 지정 섹션 갱신은 `docs_refresh_cli.py`이다.

한 파일만 볼 때: `python _tools/docs_lint.py {docs_root} --only DEV-10 --skip-schema-sync --summary-only`

## 복사한 뒤

`…`, `YYYY-MM-DD`, `{제품명}`은 자리표시라 헤더와 필수 칸에서 lint가 실패한다. 확인한 값으로 바꾸거나, 아직 모르면 그 칸에 `미결`을 쓰고 미결 표 내용에 다음에 할 일을 적는다. 실행·설치는 모르는 키의 행을 지운다. 개발·사용자·환경 중 확인된 행이 하나 이상 남아야 한다.

선택 절의 `…`는 FAKEFILL 대상이 아니다. 값을 모르면 그 행이나 절을 지운다. 선택 절을 통째로 빼도 lint는 통과한다. `extract_values.py`는 ○ 왜 필요한가의 구분·내용 표에서 행 키를 그대로 담는다. `render_doc.py`가 그 절을 다시 쓸 때는 스키마 키 `문제`·`접근`만 출력한다.

관련 문서의 DEV-20·DEV-30은 ideal 힌트에 나오는 코드이다. 그 파일이 없으면 행을 지우고, 다음에 만들 문서를 미결에 적는다. 헤더의 `관련 문서` 행은 헌법 §4의 선택 항목이라 lint 메타 키는 아니다.
