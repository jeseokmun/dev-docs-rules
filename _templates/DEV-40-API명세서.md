# 템플릿 — DEV-40 API명세서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-40-API명세서/DEV-40-{슬러그}.md` (다건)
> **용도:** 헌법 §5. HTTP 등 API 계약. 헌법 §3.3은 API가 있을 때 이 유형을 상황 권장으로 둔다. light·full의 필수 목록에는 없다.
> **가독성:** 표 우선. 산문은 요약 1–3문장 (헌법 §1.11). 내부 구현은 DEV-32나 DEV-70일 수 있으나, 그 문장이 제품의 비범위인지는 범위 칸에 확인해서 적는다.

## 문서 성숙도

| 단계 | 이 유형에서 |
|---|---|
| draft | ＊ 개요부터 ＊ 인증까지 여섯 절이 lint를 통과하면 된다 |
| 모르는 값 | 호출해 보지 않은 경로를 계약인 것처럼 쓰지 않는다 |
| 모르는 값 | 호출해 보지 않은 상태 코드를 계약인 것처럼 쓰지 않는다 |
| 모르는 값 | 칸은 `미결`이다 |
| 모르는 값 | 정말 없으면 `없음`이다 |
| 리뷰 | 보강 요청은 요청·응답 필드가 `미결`인 엔드포인트의 목록이다 |
| active | 핵심 미결이 닫혔을 때 |
| active | 에러 코드를 구현과 다시 맞춰 볼 수 있을 때 |
| active | 인증 방식을 구현과 다시 맞춰 볼 수 있을 때 |
| 어긋남 | 계약이 바뀌면 이 파일을 고친다 |
| 어긋남 | 고치지 못하면 상태를 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 개요 | 이 문서가 계약으로 다루는 API가 있는지를 적는다. HTTP만으로 한정하지 않는다 |
| ＊ 개요 | 없으면 그 이유를 다른 문장으로 적는다 |
| ＊ 개요 | 프로세스 안 함수와 도메인 계산은 넣지 않는다 |
| ＊ 개요 | Google AIP-121은 API 표면을 저장 스키마와 같게 두지 말라고 한다 |
| ＊ 엔드포인트 | 메서드는 그 호출이 하는 뜻만 적는다. 메서드, 경로, 설명이 한 행이다. RFC 9110(R. Fielding, M. Nottingham, J. Reschke, 2022) 9절은 요청의 뜻을 메서드에 두고 대상의 식별과 나누라고 한다. 코드에 없는 HTTP 메서드 이름을 짓지 않는다 |
| ＊ 엔드포인트 | API가 없으면 세 칸에 `없음`을 적는다 |
| ＊ 엔드포인트 | 그 이유는 개요와 같은 문장으로 맞춘다 |
| ＊ 엔드포인트 | 경로는 그 대상만 적는다. `/…`처럼 슬래시 뒤에만 말줄임이 있으면 칸 전체가 `…`가 아니라 자리표시로 잡히지 않는다 |
| ＊ 엔드포인트 | 설명만 적는다 |
| ＊ 요청 | 위치만 적는다 |
| ＊ 요청 | 위치, 이름, 형, 필수, 설명이 한 행이다 |
| ＊ 요청 | 받는 필드가 없으면 각 칸에 `없음` |
| ＊ 요청 | 이름만 적는다 |
| ＊ 요청 | 형만 적는다 |
| ＊ 요청 | 필수만 적는다 |
| ＊ 요청 | 설명만 적는다 |
| ＊ 응답 | 필드만 적는다 |
| ＊ 응답 | 필드, 형, 설명이 한 행이다 |

| ＊ 응답 | 형만 적는다 |
| ＊ 응답 | 설명만 적는다 |
| ＊ 에러 | 코드만 적는다 |
| ＊ 에러 | 상태 코드를 정하지 않았으면 칸은 `미결` |
| ＊ 에러 | 의미만 적는다. 다음에 정할 일은 미결에 둔다 |
| ＊ 인증 | 방식과 비고. 인증이 없으면 방식은 `없음`. 비고에는 이유를 적어도 되고, 비고는 비워도 된다. 실토큰은 헌법 §7에서 금지다 |
| ○ 버전·호환 | 항목은 그 행의 이름만 적는다 |
| ○ 버전·호환 | 내용은 확인된 지금 버전만 적는다. RFC 8259(T. Bray, 2017) 4는 이름과 값을 나눈다 |
| ○ 버전·호환 | 정하기 전이면 그 절의 자리표시 행은 두지 않는다 |
| ○ 버전·호환 | 미결 내용에 `없는 사실:`을 적는다 |
| ○ 버전·호환 | `다음 행동:`은 그 문장과 따로 적는다 |
| ○ 버전·호환 | 깨지는 변경 때 이 문서를 어떻게 할지를 확인된 것만 적는다 |

비밀 형태가 lint의 SECRET_LIKE에 걸리면 실패하고, 찾은 값은 출력하지 않는다 (`_schemas/README.md`의 비밀 패턴).

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

기준은 `_schemas/DEV-40.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다.

| 항목 | 기준 |
|---|---|
| 역할 | 프로필 필수가 아니다 |
| 역할 | 없어도 light·full 검사는 통과한다 |
| 역할 | 파일이 있으면 본문을 검사한다 |
| 경로 | `{docs_root}/DEV-40-API명세서/DEV-40-{슬러그}.md` |
| 위치 | 다건. 루트 단독 파일은 DOC_PATH |
| 제목 | `#` 줄에 `DEV-40`이 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-40. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸의 `…`는 실패한다. `GET`이나 `/v1/items`처럼 구체적인 글자는 `…`가 아니므로, 확인 전이면 그 글자를 쓰지 않는다 |
| 빈 칸 | `비고` 헤더만 예외이다 |
| 빈 칸 | ＊ 인증의 비고 칸은 비워도 된다 |
| 빈 칸 | 방식 칸은 예외가 아니다 |
| 선택 절 | 열 이름을 검사하지 않는다. 복사용 버전 열은 항목·내용, 관련 문서는 코드·경로 |
| 미결 | 스키마 열은 ID·내용. 열 이름은 검사하지 않는다. 내용 칸은 `없는 사실:` 문장과 `다음 행동:` 문장이다. 빈칸은 EMPTY_CELL이다 |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 개요 | string, min 1 | 자리표시가 아닌 1자 이상 |
| ＊ 엔드포인트 | table. 메서드, 경로, 설명. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 요청 | table. 위치, 이름, 형, 필수, 설명. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 응답 | table. 필드, 형, 설명. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 에러 | table. 코드, 의미. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시. 여기서 코드는 헤더의 문서 코드 DEV-40이 아니라 에러 코드 열이다 |
| ＊ 인증 | table. 방식, 비고. min_rows 1 | 방식의 빈 칸과 자리표시는 실패한다. 비고 열은 예외 |

## 복사한 뒤

개요와 다섯 필수 표의 `…`는 바꾸기 전에 lint가 실패한다. 엔드포인트가 없으면 메서드·경로·설명에 `없음`을 적고 개요에 이유를 한 줄로 둔다. 요청 필드가 없으면 다섯 칸 모두 `없음`이다. 인증 비고의 헌법 문장은 패키지 규칙이라 남겨도 된다. 방식 칸의 `…`는 남기면 실패한다. 버전·호환을 모르면 그 절의 자리표시 행은 두지 않는다. 미결 내용에 `없는 사실:`과 `다음 행동:`을 적는다. 관련 문서의 파일이 없으면 그 행을 만들지 않고, 다음에 만들 문서는 같은 미결 칸에 적는다.
