# 템플릿 — DEV-45 설정명세서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-45-설정명세서.md` (단건, 문서 루트)
> **용도:** 헌법 §5. 설정 키 목록. 같은 줄은 값 금지이다. 스키마에는 `기본값` 열이 있다. 그 칸에는 비밀이 아닌 형태만 적는다. 비밀 값, 토큰, 비밀번호는 헌법 §1.5와 §7에서 문서에 넣지 않는다.
> **가독성:** 표 우선. 산문은 요약 1–3문장 (헌법 §1.11).

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 헌법 §1.9 |
| ○ | 권장 절. 제품 문서에서 빼도 필수 검사에는 없다 |
| □ | 이 스키마의 표 헤더에는 □가 없다 |

## 문서 성숙도

| 단계 | 이 유형에서 |
|---|---|
| draft | ＊ 설정 키 목록과 ＊ 비밀·실값 금지가 lint를 통과하면 된다 |
| 모르는 값 | 확인하지 않은 기본값을 숫자나 주소로 지어 넣지 않는다. 칸은 `미결`. 비밀 저장소의 제품명과 경로는 확인된 것만 적는다 |
| 리뷰 | 보강 요청은 기본값이 `미결`인 키의 목록이다 |
| active | 핵심 미결이 닫히고, 비밀·실값 금지 표의 상태를 문서를 다시 읽고 맞출 수 있을 때 |
| 어긋남 | 키 이름이나 기본 형태가 바뀌면 이 파일을 고치거나 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 설정 키 목록 | 키 이름, 비밀이 아닌 기본 형태, 허용 범위, 설명. 실값과 토큰은 어느 칸에도 없다 |
| ＊ 비밀·실값 금지 | 무엇을 확인했는지와 상태. 상태 칸의 `예`는 그 확인을 한 뒤에만 쓴다. 확인 전이면 `미결` |
| ○ 환경별 차이 | 스키마 열은 키, dev, stage, prod이다. 제품의 환경 이름이 이 셋과 다르면 절을 만들지 않고, 미결에 환경 이름과 다음에 할 일을 적는다. lint는 이 선택 표의 열 이름을 보지 않는다. 열을 바꿔도 check_file은 통과한다. 이 템플릿은 스키마 열을 유지한다 |
| ○ 관련 문서 | 코드와 실제 경로. 비밀 설명은 DEV-55, 외부 서비스는 DEV-48일 수 있다. 없는 파일은 적지 않는다 |

`예 / 미결`처럼 두 상태를 슬래시로 이어 두면 확인했다는 뜻과 아직이라는 뜻이 한 칸에 섞인다 (헌법 §1.4). 상태 칸은 하나면 된다.

## 기계 검사

기준은 `_schemas/DEV-45.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다.

| 항목 | 기준 |
|---|---|
| 역할 | light·full 필수 목록에 없다. 없어도 프로필 검사는 통과한다. 파일이 있으면 본문을 검사한다 |
| 경로 | `{docs_root}/DEV-45-설정명세서.md` |
| 위치 | 단건. 폴더 안에 두면 DOC_PATH |
| 제목 | `#` 줄에 `DEV-45`가 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-45. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록. 이 상태 값은 문서 생애이고, ＊ 비밀·실값 금지 표의 상태 열과는 다른 칸이다 |
| 자리표시 | 필수 칸의 `…`는 실패한다. `형태만 (실값 금지)`처럼 설명 문장은 `…`가 아니라 그대로 두면 lint가 통과한다. 키를 모르면 그 문장으로 키 칸을 채우지 않고 `…`를 `미결`로 바꾼다 |
| 빈 칸 | `비고`와 `□` 헤더가 없다. 빈 칸은 EMPTY_CELL |
| 비밀 패턴 | 문서 전체에 SECRET_LIKE가 있으면 실패하고 찾은 값은 출력하지 않는다 |
| 선택 절 | 열 이름과 자리표시를 검사하지 않는다. 환경별 차이의 `…`는 FAKEFILL이 아니므로, 환경이 확정되기 전에 절을 지운다 |
| 미결 | 스키마 열은 ID·미결·다음에 할 일. 열 이름은 검사하지 않는다. 빈칸은 EMPTY_CELL |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 설정 키 목록 | table. 키, 기본값, 범위, 설명. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 비밀·실값 금지 | table. 확인, 상태. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시. `예`라고 적어도 검사를 했다는 사실까지 보지는 않는다 |

한 파일만 볼 때: `python _tools/docs_lint.py {docs_root} --only DEV-45 --skip-schema-sync --summary-only`

## 복사한 뒤

키 목록 네 칸과 비밀·실값 금지 두 칸의 `…`는 바꾸기 전에 lint가 실패한다. 기본값 칸에는 `파일 경로`, `정수`, `켜짐 또는 꺼짐`처럼 비밀이 아닌 형태를 적는다. 확인 칸에는 무엇을 읽었는지, 상태 칸에는 `예` 또는 `미결` 중 하나를 적는다. 환경별 차이는 dev·stage·prod가 제품의 환경 이름과 같을 때만 남긴다. 관련 문서의 코드와 경로를 모르면 절을 지운다.
