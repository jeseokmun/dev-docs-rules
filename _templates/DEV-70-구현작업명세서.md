# 템플릿 — DEV-70 구현작업명세서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「한 덩어리 구현 지시」. 파일 하나 = 작업 하나.
> **경로:** `{docs_root}/DEV-70-구현작업명세서/DEV-70-{슬러그}.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다. 헌법 §3.4의 짧은 작업 문서다. 끝나면 `{docs_root}/archive/DEV-70-구현작업명세서/`로 옮기거나, 남은 결정만 DEV-50으로 올린다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 이번 덩어리의 목표와 하지 않을 일 | ＊ 목표 / 비범위 | 제품 전체의 비범위는 DEV-20 |
| 사실, 추측, 아직 없는 사실 | ＊ 사실 · 추측 · 미결 | 스키마에 `open_items`가 없다. 별도 미결 H2를 만들지 않는다 |
| 끝나면 무엇이 성립하나 | ＊ 완료 조건 | 인수 조건의 본문은 DEV-22. 조건 칸에 그 ID를 적을 수 있다 |
| 어떤 명령이나 테스트로 보나 | ＊ 검증 | 스위트 전체는 DEV-65. 경로를 모르면 검증 칸에 명령이 아직 없다고 적고, 사실 표의 미결 행에 다음 행동을 적는다 |
| 하지 말 것 | ＊ 금지 | 아키텍처 결정은 DEV-50 |

필수 프로필에 이 코드는 없다. `archive/`로 옮긴 파일은 경로 검사와 본문 검사 대상이 아니다. `docs_lint.py`는 그 디렉터리를 건너뛴다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 다섯 절이 lint를 통과 |
| 리뷰 | 명령을 모르면 사실 표의 종류 `미결` 행에 `없는 사실:`과 `다음 행동:`을 적는다 |
| 리뷰 | 경로를 모르면 그 미결 행과 다른 문장으로 적는다. 없는 경로는 짓지 않는다 |
| active | 완료 조건마다 검증 표에 대응하는 번호가 있다 |
| active | 그 방법은 저장소에서 다시 실행할 수 있는 명령이거나 아직 없다는 문장이다 |
| 종료 | 상태를 `deprecated`로 바꾼다 |
| 종료 | 그 다음에 archive로 옮긴다. 파일을 어디로 옮길지는 승격 절에 적지 않는다 |
| 종료 | 남은 결정은 DEV-50 한 건으로 올린다. 헌법 §3.4는 DEV-20 승격을 정하지 않는다 |
| 종료 | 그 DEV-50 파일의 경로만 ○ 관련에 적는다. RFC 3986(T. Berners-Lee, R. Fielding, L. Masinter, 2005) 1.1은 식별자가 그 대상의 상태까지 담는다고 보지 말라고 한다. 경로 칸에 상태 단어를 붙이지 않는다. 없는 경로는 짓지 않는다 |
| 종료 | 요구 변경이 필요하면 그 사실을 미결 행에 적는다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다. `목표 / 비범위`와 `사실 · 추측 · 미결`의 공백과 가운데점은 스키마와 같다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 목표 / 비범위 | 목표 행은 이번 덩어리가 끝나면 성립하는 일이다 |
| ＊ 목표 / 비범위 | 열은 `구분`·`내용`이고 최소 1행이다 |
| ＊ 목표 / 비범위 | 구분은 자유 글이라 `목표`를 여러 행에 써도 된다 |
| ＊ 목표 / 비범위 | 비범위 행은 이번 작업이 고치지 않는 일이다. `비범위`를 여러 행에 써도 된다 |
| ＊ 사실 · 추측 · 미결 | 사실 행은 확인한 내용만 적는다. 열 `종류`·`내용`, 최소 1행. 칸을 비우면 `EMPTY_CELL`이다 |
| ＊ 사실 · 추측 · 미결 | 추측 행은 헌법 §1 원칙 4대로 내용을 `추측:`으로 시작한다 |
| ＊ 사실 · 추측 · 미결 | 미결 행의 내용에는 `없는 사실:` 문장을 둔다 |
| ＊ 사실 · 추측 · 미결 | 미결 행의 내용에는 `다음 행동:` 문장을 둔다 |
| ＊ 완료 조건 | 열 `#`·`조건`, 최소 1행. |
| ＊ 검증 | 번호는 완료 조건의 번호와 맞춘다. 열 `#`·`방법`, 최소 1행 |
| ＊ 검증 | 방법은 명령, 테스트 이름, 또는 아직 정하지 않았다는 문장이다 |
| ＊ 금지 | 열 `금지`·`이유`, 최소 1행. 금지가 없으면 금지 칸에 그 사실을 적는다 |
| ＊ 금지 | 금지가 없으면 이유 칸에 이번 작업의 범위를 적는다 |
| ○ 관련 | 열 `종류`·`링크`. 있는 경로만. |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-70.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-70-구현작업명세서/DEV-70-{슬러그}.md` |
| 위치 | 다건. 폴더 밖 파일은 `DOC_PATH` |
| 헤더 | 스키마 메타는 `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-70`. 날짜는 달력의 `YYYY-MM-DD`. `수명` 키는 메타가 아니라 lint가 읽지 않는다 |
| 제목 | `^#` 줄에 `DEV-70`이 단어로 있다 |

| 필수 제목 | 열 순서 | 최소 행 |
|---|---|---|
| ＊ 목표 / 비범위 | 구분, 내용 | 1 |
| ＊ 사실 · 추측 · 미결 | 종류, 내용 | 1 |
| ＊ 완료 조건 | #, 조건 | 1 |
| ＊ 검증 | #, 방법 | 1 |
| ＊ 금지 | 금지, 이유 | 1 |

필수 칸의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. 선택 표의 `…`는 `FAKEFILL`이 아니다. lint는 `추측:` 접두사와 완료 조건·검증 번호의 짝을 보지 않는다. 스키마 `rules`는 실행되지 않는다. 복사용 본문에 `## 미결`을 두지 않는다. 아직 없는 사실과 다음 행동은 사실 표의 종류 `미결` 행에 `없는 사실:`과 `다음 행동:`으로 적는다.

## 작성 규칙

- 헤더 범위는 이번 덩어리, 헤더 비범위는 이번 작업이 건드리지 않는 이웃 문서의 책임이다.
- 승격 절은 이번 작업에서 남는 결정을 다른 문서로 올리는 일만 적는다. 올릴 DEV-50이 있으면 그 제목, 없으면 승격할 결정이 없다는 문장을 적는다. 파일을 어디로 옮길지는 이 절에 적지 않는다.
- 종료 절은 이 파일을 archive로 옮기는 일만 적는다. archive로 옮겼는지 또는 아직 진행 중인지를 적는다. 채택 문장은 넣지 않는다.
- 슬러그는 lint가 검사하지 않는다. 헌법의 예는 `DEV-70-1234-로그인`이다. 그 번호 체계가 이 저장소의 규칙이라는 뜻은 아니다.
- 비밀과 개인정보 샘플은 검증 명령의 인자로 적지 않는다.
