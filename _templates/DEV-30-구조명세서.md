# 템플릿 — DEV-30 구조명세서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-30-구조명세서.md` (단건, 문서 루트)
> **용도:** 헌법 §5. 모듈 경계, 의존, Mermaid 구조.
> **가독성:** 표와 Mermaid. 산문은 요약 1–3문장 (헌법 §1.11). 표시 라벨은 DOC-CONFIG language와 같게 한다 (헌법 §1.8).

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 헌법 §1.9 |
| ○ | 권장 절. 제품 문서에서 빼도 필수 검사에는 없다 |
| □ | 헤더에 있으면 그 칸은 빈 값·자리표시의 lint 예외. ＊ 건드리기 위험 구역의 `경로(□)`가 그 예외이다. ＊ 모듈/레이어의 `비고` 열도 예외이다 |

## 문서 성숙도

| 단계 | 이 유형에서 |
|---|---|
| draft | 아래 ＊ 다섯 절이 lint를 통과하면 된다. min_nodes 4와 라벨 언어는 사람 검토이고 draft 탈락 조건이 아니다 |
| 모르는 값 | 없는 모듈 이름을 지어 넣지 않는다. 칸은 `미결`, 미결 표에는 다음에 코드에서 확인할 일 |
| 리뷰 | 보강 요청은 의존 방향이 비어 있는 모듈의 목록이다 |
| active | 핵심 미결이 닫히고, 구조도의 모듈 이름을 저장소와 다시 맞춰 볼 수 있을 때 |
| 어긋남 | 코드의 의존이 문서와 다르면 문서를 고치거나 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 한 줄 구조 요약 | 모듈이 어떻게 나뉘고 의존이 어느 쪽으로 가는지 한 문장. 스키마는 의존이 한 방향이어야 한다고 정하지 않는다 |
| ＊ 모듈/레이어 | 모듈, 책임, 호출 쪽 메모. 최소 3행. `비고`는 비워도 된다 |
| ＊ 구조도 (Mermaid) | 모듈 사이 호출을 mermaid 펜스로 그린다. 사람 검토 값 min_nodes는 4이다. 노드를 세는 코드는 lint에 없다. ko이면 표시 라벨에 한글이 있게 한다 |
| ＊ 의존 규칙 | 방향마다 허용 여부와 설명. 최소 2행. `허용?` 칸에는 확인된 허용 또는 금지를 적는다 |
| ＊ 건드리기 위험 구역 | 잘못 고치면 깨지는 모듈과 이유. 경로를 모르면 `경로(□)`를 비운다 |
| ○ 핵심 실행 흐름 | 스키마 type은 table_or_mermaid이다. 열은 단계·행위자·행동이거나, 시퀀스 그림이다. lint는 이 선택 절을 보지 않는다 |
| ○ 데이터 위치 | 확인된 저장 장소만 위치 칸에 적는다. 열은 데이터·위치 |
| ○ 관련 문서 | 코드와 실제 경로. 개요는 DEV-10일 수 있다. 없는 파일은 적지 않는다 |

이상형 힌트는 `python _tools/ideal_check_min.py {docs_root} --summary-only`이다. draft 탈락이 아니다. 없는 경로나 문서 코드를 힌트에 맞추려고 넣지 않는다.

| 힌트 | `_tools/ideal_check_min.py`가 보는 것 |
|---|---|
| 경로 | 백틱 안에 `/src`, `/lib`, `/app`, `/Assets`가 있거나, 백틱 안이 `.ts` `.tsx` `.js` `.dart` `.cs` `.py`로 끝난다. 저장소 트리와 같은지는 SKIP |
| 연결 | 본문에 DEV-35 또는 DEV-50이 없으면 FAIL. 도구의 실패 문구는 light에서 그 파일이 없는 일이 흔하다고 적는다 |
| 테스트 | `테스트`, `test`, DEV-65가 없으면 FAIL |
| Mermaid | 펜스가 없으면 존재 힌트가 FAIL. 펜스가 있고 language가 ko인데 한글이 없으면 라벨 힌트가 FAIL. ko가 아니면 라벨 힌트는 SKIP |
| SKIP | 실패·멱등 흐름의 품질 |

모양 예시이다. `가칭가`부터 `가칭라`는 제품 모듈이 아니다.

```mermaid
flowchart LR
  가칭가 --> 가칭나
  가칭나 --> 가칭다
  가칭다 --> 가칭라
```

## 기계 검사

기준은 `_schemas/DEV-30.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다. 스키마 `rules`의 `mermaid_visible_labels_match_language`는 별도 엔진으로 실행되지 않는다.

| 항목 | 기준 |
|---|---|
| 역할 | light의 필수 문서. full도 포함한다. 없으면 MISSING |
| 경로 | `{docs_root}/DEV-30-구조명세서.md` |
| 위치 | 단건. 다른 경로면 DOC_PATH |
| 제목 | `#` 줄에 `DEV-30`이 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-30. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸과 헤더의 `…`, `YYYY-MM-DD`, `{한 조각}` 등은 실패한다. `비고` 열과 `□`가 들어간 헤더는 예외 |
| 빈 칸 | 그 두 예외를 뺀 빈 칸은 모든 표에서 EMPTY_CELL |
| 선택 절 | 없어도 통과하고 열 이름을 검사하지 않는다. 복사용 열은 스키마 columns와 같다 |
| 미결 | 스키마 열은 ID·내용. 열 이름은 검사하지 않는다. 빈칸 대신 `미결`과 다음에 할 일을 내용에 적는다 |
| Mermaid | 필수 절에 비어 있지 않은 ` ```mermaid ` 펜스가 있어야 한다. HTML 주석만 있으면 주석을 지운 뒤 펜스가 없어 MISSING_MERMAID이다. 문법과 노드 수는 자동 실패가 아니다 |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 한 줄 구조 요약 | string, min 1 | 자리표시가 아닌 1자 이상 |
| ＊ 모듈/레이어 | table. 모듈, 책임, 비고. min_rows 3 | 모듈·책임의 빈 칸과 자리표시는 실패한다. 비고 열은 예외. 3행 이상 |
| ＊ 구조도 (Mermaid) | mermaid. min_nodes 4는 사람 검토 | 비어 있지 않고 자리표시가 아닌 펜스 |
| ＊ 의존 규칙 | table. 방향, 허용?, 설명. min_rows 2 | 열 순서, 2행 이상, 빈 칸, 자리표시 |
| ＊ 건드리기 위험 구역 | table. 모듈, 이유, 경로(□). min_rows 1 | 모듈·이유의 빈 칸과 자리표시는 실패한다. 경로(□)는 예외 |

생성기는 DEV-10과 DEV-30만 있다. `render_doc.py`는 mermaid 문자열의 줄바꿈이 2개 미만이면 구조도 절을 빼고 미결에 `＊ 구조도 (Mermaid) 미기입`을 넣는다. 모듈이 3행 미만이어도 그 절을 빼고 미결로 보낸다. 저장된 파일에 필수 H2가 없으면 lint는 실패한다. 초안은 `docs_draft_cli.py`, 지정 섹션 갱신은 `docs_refresh_cli.py`이다.

한 파일만 볼 때: `python _tools/docs_lint.py {docs_root} --only DEV-30 --skip-schema-sync --summary-only`

## 복사한 뒤

요약, 모듈, 책임, 의존의 세 칸, 위험 구역의 모듈과 이유에 `…`가 있으면 lint가 실패한다. 비고와 경로(□)는 비어 있어도 그 칸은 통과한다.

구조도 절에 설명 문장만 있으면 펜스가 없어 MISSING_MERMAID이다. 위의 가칭 그림을 복사한 뒤 노드 이름을 제품 모듈로 바꾼다. 가칭을 그대로 두면 lint는 통과한다. active 전에 제품 이름으로 바꾼다.

선택 절은 내용을 모르면 지운다.
