# 템플릿 — DEV-32 모듈명세서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-32-모듈명세서/DEV-32-{슬러그}.md` (다건)
> **용도:** 헌법 §5. 한 모듈의 책임과 인터페이스. 전체 구조는 DEV-30이다 (헌법 §1.2, §1.6).
> **가독성:** 표 우선. 산문은 요약 1–3문장 (헌법 §1.11).

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 헌법 §1.9 |
| ○ | 권장 절. 제품 문서에서 빼도 필수 검사에는 없다 |
| □ | ＊ 건드리기 위험의 `경로(□)`는 빈 값·자리표시의 lint 예외 |

## 문서 성숙도

| 단계 | 이 유형에서 |

| 모르는 값 | 호출 시그니처를 지어 넣지 않는다 |
| 모르는 값 | 칸은 `미결` |

| active | 핵심 미결이 닫혔을 때 |
| active | 공개 인터페이스를 코드와 다시 맞춰 볼 수 있을 때 |
| 어긋남 | 이 파일의 모듈 경계가 바뀌면 이 파일을 고친다 |
| 어긋남 | DEV-30의 모듈 경계가 바뀌면 DEV-30을 고친다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 모듈 | 이름은 모듈 이름이다 |
| ＊ 모듈 | 이름, 하는 일, 입력, 출력이 한 행이다 |
| ＊ 모듈 | 한 파일에 한 모듈이 기본이다 |
| ＊ 모듈 | 최소 1행이다 |
| ＊ 모듈 | 책임은 하는 일만 적는다 |
| ＊ 모듈 | 하지 않는 일이 있으면 그 문장만 따로 적는다 |
| ＊ 공개 인터페이스 | 이름은 그 인터페이스의 이름이다. 이름, 종류, 입력, 출력이 한 행이다 |
| ＊ 공개 인터페이스 | 종류는 확인된 함수, 이벤트, API 중 해당하는 것만 적는다 |
| ＊ 공개 인터페이스 | 입력만 적는다. 타입 이름을 모르면 입력 칸은 `미결` |
| ＊ 공개 인터페이스 | 출력은 반환만 적는다. 타입 이름을 모르면 출력 칸은 `미결`. Martin Fowler의 Command Query Separation(2005-12-05)은 상태를 바꾸는 일과 반환을 나눈다. 저장되는 필드는 DEV-35에 둔다 |
| ＊ 의존 | 대상만 적는다. 대상, 방향, 허용 여부, 설명이 한 행이다 |
| ＊ 의존 | 방향만 적는다 |
| ＊ 의존 | 허용 여부는 확인된 허용 또는 금지다. `허용?` 칸에 적는다 |
| ＊ 의존 | 설명만 적는다. DEV-30에 같은 규칙이 있으면 문장을 복붙하지 않고 설명 칸에 그 경로를 적는다 |
| ＊ 건드리기 위험 | 깨지면 무엇이 달라지는지만 적는다 |
| ＊ 건드리기 위험 | 경로를 모르면 `경로(□)`를 비운다 |
| ○ 불변조건·실패 시 | 조건은 항상 지킬 것만 적는다. 열은 조건·실패 시. 모르면 그 절의 자리표시 행은 두지 않는다. 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 시작한다 |
| ○ 불변조건·실패 시 | 실패 시는 실패하면 보이는 결과만 적는다 |
| ○ 관련 문서 | 코드는 그 문서의 코드만 적는다 |
| ○ 관련 문서 | DEV-30이 있으면 그 경로만 적는다. 경로 칸에는 경로만 적는다. 없는 경로는 짓지 않는다 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준은 `_schemas/DEV-32.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다.

| 항목 | 기준 |
|---|---|
| 역할 | light·full 필수 목록에 없다 |
| 역할 | 없어도 프로필 검사는 통과한다 |
| 역할 | 파일이 있으면 본문을 검사한다 |
| 경로 | `{docs_root}/DEV-32-모듈명세서/DEV-32-{슬러그}.md` |
| 위치 | 다건. 루트 단독 파일은 DOC_PATH |
| 제목 | `#` 줄에 `DEV-32`가 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-32. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸의 `…`는 실패한다 |
| 자리표시 | `경로(□)`만 예외이다 |
| 자리표시 | `미결`은 자리표시가 아니다 |
| 자리표시 | `없음`은 자리표시가 아니다 |
| 빈 칸 | `□`가 없는 헤더의 빈 칸은 EMPTY_CELL |
| 선택 절 | 열 이름을 검사하지 않는다 |
| 선택 절 | 복사용 열은 스키마와 같다 |
| 미결 | 스키마 열은 ID·미결·다음에 할 일. 열 이름은 검사하지 않는다. 빈칸은 EMPTY_CELL |

칸 전체가 `함: … / 안 함: …`이면 자리표시 목록의 `…`와 같지 않아 FAKEFILL에 걸리지 않는다. 그래서 복사용 필수 칸은 `…` 한 조각으로 두어, 채우기 전에 lint가 실패하게 했다.

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 모듈 | table. 모듈, 책임, 입력, 출력. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 공개 인터페이스 | table. 이름, 종류, 입력, 출력. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 의존 | table. 대상, 방향, 허용?, 설명. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 건드리기 위험 | table. 구역, 영향, 경로(□). min_rows 1 | 구역·영향의 빈 칸과 자리표시는 실패한다. 경로(□)는 예외 |

한 파일만 볼 때: `python _tools/docs_lint.py {docs_root} --only DEV-32 --skip-schema-sync --summary-only`

## 복사한 뒤

필수 칸의 `…`는 확인한 값이나 `미결`로 바꾸기 전에 lint가 실패한다. 인터페이스와 의존이 둘 이상이면 행을 더한다. 방향 칸에는 이 모듈에서 대상으로, 또는 그 반대로를 확인된 대로 적는다. 경로(□)는 비워 둘 수 있다. 불변조건을 모르면 그 절의 자리표시 행은 두지 않는다. 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 시작한다. 관련 문서의 파일이 없으면 그 행을 만들지 않는다. DEV-30 행의 `…`는 선택 표라 FAKEFILL이 아니므로, 경로를 모르면 그 행은 두지 않고 같은 미결 칸에 적는다.
