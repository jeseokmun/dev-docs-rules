# DEV-50 기술결정기록 — 로컬 DB는 drift

| 필드 | 값 |
|---|---|
| 상태 | draft |
| 코드 | DEV-50 |
| 마지막 갱신 | 2026-10-13 |
| 결정 상태 | proposed |
| 범위 | v1 로컬 저장 라이브러리의 후보 |
| 비범위 | 테이블 필드(DEV-35), 첫 설치 절차(DEV-38), 날짜 경계 값의 확정 |
| 관련 문서 | 아래 ○ 관련 표 |

## ＊ 제목
로컬 DB 후보로 drift를 둔다. 이 기록의 결정 상태는 proposed이며 accepted가 아니다. 필드 정의는 DEV-35, 첫 설치는 DEV-38이다. 날짜 경계 값은 HC-MIDNIGHT. 주인은 `../DEV-70-구현작업명세서/DEV-70-001-오늘체크-유스케이스.md`다. 이 기록은 라이브러리 후보만 다룬다.

## ＊ 맥락
저장은 DEV-10. 구조는 DEV-30. 그래서 마이그레이션과 타입을 가진 로컬 SQL 계층이 필요하다. 이 패키지에는 HabitCheck 앱 코드와 `pubspec.lock`이 없다(DEV-72).

## ＊ 결정
`infrastructure`의 기본 후보는 drift다. accepted는 아래 되돌리는 조건의 스파이크가 끝난 뒤에만 올린다. 스파이크 전에는 DEV-30 인프라 행에 제품명을 적지 않는다.

## ＊ 이유
| # | 이유 |
|---|---|
| 1 | 스키마와 쿼리를 컴파일 때에 검사하면 streak·날짜 실수를 줄일 수 있다는 점이 후보를 고른 이유다. 이 패키지에서 그 감소를 측정하지는 않았다 |
| 2 | 마이그레이션을 파일로 두면 DEV-30 위험 구역의 계획 경로를 나중에 채울 수 있다. 지금 `lib/infrastructure/db/migrations/`는 이 패키지에 없다 |

## ＊ 버린 대안
| 대안 | 버린 이유 |
|---|---|
| SharedPreferences만 사용 | 관계형 체크인과 주간 집계에 곧 한계가 있다. 측정한 건수 한계는 아니다 |
| sqflite를 직접 사용 | 동작은 가능하나 타입과 마이그레이션 규율이 drift 후보보다 약하다는 판단이다. 버전을 나란히 재어 비교한 표는 없다 |

## ○ 결과·리스크
| 항목 | 내용 |
|---|---|
| 결과 | 학습량과 생성 코드가 늘 수 있다. 크기는 측정하지 않았다. DEV-72는 학습이 1일 안에 끝날 수 있다고 추측으로 적고, 측정값이 아니라고 적는다 |
| 리스크 | HC-DRIFT-VER |

## ○ 되돌리는 조건
| 조건 | 다음 행동 |
|---|---|
