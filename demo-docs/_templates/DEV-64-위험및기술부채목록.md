# 템플릿 — DEV-64 위험및기술부채목록 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「알고 있는 위험과 갚지 않은 기술부채」. 제품당 파일 하나. arc42 11번의 알려진 문제 목록이다.
> **경로:** `{docs_root}/DEV-64-위험및기술부채목록.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 아직 고르지 않은 문제, 갚지 않은 구현 공백 | ＊ 항목 | 왜 골랐는지는 DEV-50. 그 결정의 결과·리스크 행을 여기로 옮기지 않는다 |
| 보안 위협의 분류와 대응 | 적지 않는다 | DEV-55. STRIDE 여섯 이름을 이 표의 종류로 쓰지 않는다 |
| 이미 보였거나 예상한 한 사례 | 적지 않는다 | DEV-62. 사실과 추측을 이 파일에서 다시 재판하지 않는다 |
| 만지지 말아야 할 모듈 | 적지 않는다 | DEV-30·DEV-32의 위험 구역 |

필수 프로필에 이 코드는 없다. 파일이 없으면 본문 검사를 하지 않는다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | ＊ 항목이 1행 이상이다 |
| draft | lint를 통과한다 |
| 리뷰 | 각 행이 결정에 들어가지 않는지 본다 |
| 리뷰 | 각 행이 사례에 들어가지 않는지 본다 |
| 리뷰 | 각 행이 보안 위협에 들어가지 않는지 본다 |
| 리뷰 | 각 행이 모듈 위험 구역에 들어가지 않는지 본다 |
| active | 갚는 조건이 닫히면 그 행을 지우지 않는다 |
| active | 닫힌 이유는 조건 칸에 남긴다 |
| deprecated | 목록 자체가 다른 문서로 옮겨지면 이 파일을 deprecated로 둔다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 항목 | 종류는 `위험` 또는 `기술부채`만이다. 열 `항목`·`종류`·`영향`·`갚는 조건`, 최소 1행 |
| ＊ 항목 | 등록된 사실은 id와 경로만 적는다 |
| ＊ 항목 | 없는 번호를 만들지 않는다 |
| ＊ 항목 | 없는 날짜를 만들지 않는다 |
| ＊ 항목 | 영향은 지금 남는 공백만 적는다 |
| ＊ 항목 | 갚는 조건은 행을 닫는 관찰만 적는다. Martin Fowler의 Technical Debt(2019-05-21)는 그 공백을 치우는 일과, 공백이 있는 동안 드는 추가 노력을 나눈다. 날 수를 짓지 않는다 |
| ○ 관련 문서 | 열 `코드`·`경로`. 본문이 가리키는 `DEV-숫자`마다 있는 파일만. |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-64.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-64-위험및기술부채목록.md` |
| 위치 | 단건. 폴더 안 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-64`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-64`가 단어로 있다 |
| ＊ 항목 | 열 순서 `항목`, `종류`, `영향`, `갚는 조건`. 최소 1행. `종류`가 `위험`·`기술부채` 밖이면 `COLUMN_VALUE` |

미결 열은 `ID`·`미결`·`다음에 할 일`이다. lint는 그 열 이름을 보지 않는다. 스키마 `rules`는 실행되지 않는다.

## 작성 규칙

- 한 행은 위험 아니면 기술부채다. 둘 다이면 행을 나눈다.
- 결정이 된 내용은 DEV-50으로 옮기고, 여기 조건 칸에는 그 경로만 남긴다.
- 사례가 되면 DEV-62로 옮긴다. 이 목록에 사고 번호를 지어 넣지 않는다.
- 값이 없는 id의 번호를 영향 칸에 채우지 않는다.
