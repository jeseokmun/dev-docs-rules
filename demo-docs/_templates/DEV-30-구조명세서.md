## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 한 줄 구조 요약 | 모듈이 어떻게 나뉘는지 |
| ＊ 한 줄 구조 요약 | 의존이 어느 쪽으로 가는지. 스키마는 의존이 한 방향이어야 한다고 정하지 않는다. W3C WCAG 2.2 Understanding 1.3.2 Meaningful Sequence는 순서가 뜻을 바꾸면 그 순서를 읽을 수 있게 두라고 한다. 호출이 이어지면 문장을 나눈다 |
| ＊ 모듈/레이어 | 모듈은 그 행의 이름이다. 최소 3행 |
| ＊ 모듈/레이어 | 책임은 그 모듈의 책임만 적는다 |
| ＊ 모듈/레이어 | 비고는 호출 쪽 메모다. `비고`는 비워도 된다 |
| ＊ 구조도 (Mermaid) | 모듈 사이 호출을 mermaid 펜스로 그린다. 사람 검토 값 min_nodes는 4이다. 노드를 세는 코드는 lint에 없다 |
| ＊ 구조도 (Mermaid) | ko이면 표시 라벨에 한글이 있게 한다 |
| ＊ 구조도 (Mermaid) | 한 그림의 배율은 ○ C4 수준 한 행과 같다 |
| ○ C4 수준 | `수준`은 시스템 맥락, 컨테이너, 컴포넌트, 코드의 네 단어만 쓴다. 한 그림에 배율을 섞지 않는다. Simon Brown의 C4는 그 네 배율이다. 맥락과 컨테이너만으로 충분한 팀이 많고, 코드 그림은 보통 손으로 그리지 않는다 |
| ○ C4 수준 | C4의 컨테이너는 따로 실행되는 앱이나 저장소다 |
| ○ C4 수준 | 이미지 이름이 아니다 |
| ＊ 의존 규칙 | 허용 여부는 확인된 허용 또는 금지다. 방향마다 한 행이고, 최소 2행이다. `허용?` 칸에 적는다 |
| ＊ 의존 규칙 | 설명은 그 방향의 설명만 적는다 |
| ＊ 건드리기 위험 구역 | 모듈은 잘못 고치면 깨지는 모듈만 적는다 |
| ＊ 건드리기 위험 구역 | 이유만 적는다 |
| ＊ 건드리기 위험 구역 | 경로를 모르면 `경로(□)`를 비운다 |
| ○ 핵심 실행 흐름 | 단계는 시간 순서의 한 차례다. arc42 6번 런타임 뷰다. 시간 순서의 시나리오 하나이고, ＊ 구조도의 정적 그림을 여기서 다시 그리지 않는다. ○ C4 수준은 필수 구조도만 말한다. 이 절에 배율 행을 두지 않는다. 스키마 type은 table_or_mermaid이다. 열은 단계·행위자·행동이거나 시퀀스 그림이다. lint는 이 선택 절의 열 이름을 보지 않는다 |
| ○ 핵심 실행 흐름 | 행위자만 적는다 |
| ○ 핵심 실행 흐름 | 행동은 그 호출만 적는다. Alistair Cockburn의 Hexagonal Architecture(2005-09-04)는 유스케이스를 애플리케이션 경계의 포트에 적는다. 데이터베이스라는 바깥 기술은 그 칸에 두지 않는다. 화면이 DB를 여는 금지는 ＊ 의존 규칙에 둔다. Martin Fowler의 Replacing Throwing Exceptions with Notification(2014-12-09)는 예외적인 처리를 본 흐름 밖에 두라고 한다. 성공 단계의 행동 칸에 아직 정하지 않은 실패 반환을 적지 않는다. 그 반환은 미결에 둔다. 알림 객체는 만들지 않는다. Google developer documentation style guide의 Procedures는 한 단계에 한 동작만 둔다. 만들기와 계산과 반환을 한 단계에 같이 적지 않는다 |
| ○ 데이터 위치 | 데이터만 적는다. 열은 데이터·위치 |
| ○ 데이터 위치 | 위치는 확인된 저장 장소만 적는다 |
| ○ 관련 문서 | 코드는 그 문서의 코드만 적는다. 개요는 DEV-10일 수 있다 |
| ○ 관련 문서 | 경로는 있는 파일만 적는다. 경로 칸에는 경로만 적는다. 없는 경로는 짓지 않는다 |
| ○ 관련 문서 | 파일이 없으면 행을 넣지 않는다 |

이상형 힌트는 `python _tools/ideal_check_min.py {docs_root} --summary-only`이다. draft 탈락이 아니다. 없는 경로나 문서 코드를 힌트에 맞추려고 넣지 않는다.

| 힌트 | `_tools/ideal_check_min.py`가 보는 것 |
|---|---|
| 경로 | 백틱 안에 `/src`, `/lib`, `/app`, `/Assets`가 있거나, 백틱 안이 `.ts` `.tsx` `.js` `.dart` `.cs` `.py`로 끝난다. 저장소 트리와 같은지는 SKIP |
| 연결 | 본문에 DEV-35 또는 DEV-50이 없으면 FAIL. 도구의 실패 문구는 light에서 그 파일이 없는 일이 흔하다고 적는다 |
| 테스트 | `테스트`, `test`, DEV-65가 없으면 FAIL |
| Mermaid | 펜스가 없으면 존재 힌트가 FAIL. 펜스가 있고 language가 ko인데 한글이 없으면 라벨 힌트가 FAIL. ko가 아니면 라벨 힌트는 SKIP |
| SKIP | 실패·멱등 흐름의 품질 |

모양 예시이다. `가칭가`부터 `가칭라`는 제품 모듈이 아니다.

```mermaid
flowchart LR
  가칭가 --> 가칭나
  가칭나 --> 가칭다
  가칭다 --> 가칭라
```

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준은 `_schemas/DEV-30.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다. 스키마 `rules`의 `mermaid_visible_labels_match_language`는 별도 엔진으로 실행되지 않는다.

| 항목 | 기준 |
|---|---|
| 역할 | light의 필수 문서. full도 포함한다. 없으면 MISSING |
| 경로 | `{docs_root}/DEV-30-구조명세서.md` |
| 위치 | 단건. 다른 경로면 DOC_PATH |
| 제목 | `#` 줄에 `DEV-30`이 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-30. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸과 헤더의 `…`, `YYYY-MM-DD`, `{한 조각}` 등은 실패한다. `비고` 열과 `□`가 들어간 헤더는 예외 |
| 빈 칸 | 그 두 예외를 뺀 빈 칸은 모든 표에서 EMPTY_CELL |
| 선택 절 | 없어도 통과한다. ○ C4 수준이 있으면 열 순서는 `수준`, `이 문서에서`, `그리지 않는 것`이고 `수준`은 시스템 맥락·컨테이너·컴포넌트·코드 중 하나다. 아니면 `TABLE_COLUMNS` 또는 `COLUMN_VALUE`다. 그 밖의 선택 절 열 이름은 검사하지 않는다 |
| 미결 | 스키마 열은 ID·내용. 열 이름은 검사하지 않는다. 내용 칸은 `없는 사실:` 문장과 `다음 행동:` 문장이다. 빈칸은 EMPTY_CELL이다. 생성기가 넣는 `{절 이름} 미기입`은 그 두 문장이 아니다 |
| Mermaid | 필수 절에 비어 있지 않은 ` ```mermaid ` 펜스가 있어야 한다. HTML 주석만 있으면 주석을 지운 뒤 펜스가 없어 MISSING_MERMAID이다. 문법과 노드 수는 자동 실패가 아니다 |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 한 줄 구조 요약 | string, min 1 | 자리표시가 아닌 1자 이상 |
| ＊ 모듈/레이어 | table. 모듈, 책임, 비고. min_rows 3 | 모듈·책임의 빈 칸과 자리표시는 실패한다. 비고 열은 예외. 3행 이상 |
| ＊ 구조도 (Mermaid) | mermaid. min_nodes 4는 사람 검토 | 비어 있지 않고 자리표시가 아닌 펜스 |
| ＊ 의존 규칙 | table. 방향, 허용?, 설명. min_rows 2 | 열 순서, 2행 이상, 빈 칸, 자리표시 |
| ＊ 건드리기 위험 구역 | table. 모듈, 이유, 경로(□). min_rows 1 | 모듈·이유의 빈 칸과 자리표시는 실패한다. 경로(□)는 예외 |

생성기는 DEV-10과 DEV-30만 있다. `render_doc.py`는 mermaid 문자열의 줄바꿈이 2개 미만이면 구조도 절을 빼고 미결에 `＊ 구조도 (Mermaid) 미기입`을 넣는다. 모듈이 3행 미만이어도 그 절을 빼고 미결로 보낸다. 저장된 파일에 필수 H2가 없으면 lint는 실패한다. 초안은 `docs_draft_cli.py`, 지정 섹션 갱신은 `docs_refresh_cli.py`이다.

한 파일만 볼 때: `python _tools/docs_lint.py {docs_root} --only DEV-30 --skip-schema-sync --summary-only`

## 복사한 뒤

요약, 모듈, 책임, 의존의 세 칸, 위험 구역의 모듈과 이유에 `…`가 있으면 lint가 실패한다. 비고와 경로(□)는 비어 있어도 그 칸은 통과한다.

구조도 절에 설명 문장만 있으면 펜스가 없어 MISSING_MERMAID이다. 위의 가칭 그림을 복사한 뒤 노드 이름을 제품 모듈로 바꾼다. 가칭을 그대로 두면 lint는 통과한다. active 전에 제품 이름으로 바꾼다.

선택 절을 모르면 그 자리표시 행은 두지 않는다. 미결 내용에 `없는 사실:`과 `다음 행동:`을 적는다.
