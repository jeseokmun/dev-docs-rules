# 템플릿 — DEV-25 화면정의서 (v2.1)

> **v1 기준본 양식.** 개정할 때는 이 템플릿과 헌법 §0을 함께 고친다.
> **경로:** `{docs_root}/DEV-25-화면정의서/DEV-25-{슬러그}.md` (다건)
> **용도:** 헌법 §5. 화면 목록·흐름이고 시안은 링크이다. 이 스키마는 화면마다 파일 하나다. 화면 목록 전체를 모으는 절은 없다.
> **가독성:** 표 우선. 산문은 요약 1–3문장 (헌법 §1.11). 문구 전문은 DEV-28이다. 스크린샷과 픽셀 시안은 헌법 §1.10에서 강제하지 않는다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 헌법 §1.9 |
| ○ | 권장 절. 제품 문서에서 빼도 필수 검사에는 없다 |
| □ | 스키마 밖 선택. `□ 시안`은 required·optional 라벨이 아니다 |

## 문서 성숙도

| 단계 | 이 유형에서 |
|---|---|
| draft | ＊ 화면 목적, ＊ 진입·이탈, ＊ 주요 UI 요소, ＊ 상태가 lint를 통과하면 된다 |
| 모르는 값 | 보이지 않는 버튼이나 상태를 지어 넣지 않는다. 칸은 `미결`, 미결 표에는 다음에 확인할 일 |
| 리뷰 | 보강 요청은 비어 있는 요소와 상태의 목록이다 |
| active | 핵심 미결이 닫히고, 진입·이탈과 상태 표를 화면과 다시 맞춰 볼 수 있을 때 |
| 어긋남 | 화면이 바뀌면 이 파일을 고치거나 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 화면 목적 | 그 화면에서 사용자가 끝내는 일이 한 문장이다 |
| ＊ 진입·이탈 | 어디서 들어오고 어디로 나가는지. 열은 구분·경로인 table이다. 행 키 목록은 없다. 복사용 `진입`·`이탈`은 제안 행이고, 경로가 더 있으면 행을 더한다 |
| ＊ 주요 UI 요소 | 보이는 요소와 그 요소의 동작이 한 행이다. 카피 전문은 쓰지 않고 DEV-28 키를 동작 칸에 가리킬 수 있다 |
| ＊ 상태 | 상태가 다를 때 사용자에게 보이는 것. 복사용 `로딩`·`빈 화면`·`오류`는 빠지기 쉬운 예시이다. 제품에 없는 상태는 행을 지우고, 있는 상태는 행을 더한다 |
| ○ 접근 | Android 접근성 안내의 content label이다. 누르는 요소마다 읽는 이름이 있다. 문구 전문은 DEV-28 키로 가리킨다. 대비 비율이나 점수는 만들지 않는다. 열은 `요소`·`읽는 이름`·`확인`. 아직 키가 없으면 그 사실을 적고 이름을 짓지 않는다 |
| ○ 흐름 (Mermaid) | 스키마 type은 string이다. 표 열이 없다. 화면 이동을 적을 때 mermaid 펜스를 넣는다. 표시 라벨은 DOC-CONFIG language를 따른다 (헌법 §1.8). lint는 이 선택 절의 펜스와 문법을 보지 않는다 |
| □ 시안 | 종류와 링크. 헌법 §5의 시안은 링크이다. 제품 문서에 이 제목이 없어도 lint는 통과한다 |
| ○ 관련 문서 | 코드와 실제 경로. 문구는 DEV-28일 수 있다. 없는 파일은 행으로 두지 않는다 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준은 `_schemas/DEV-25.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다.

| 항목 | 기준 |
|---|---|
| 역할 | light·full 필수 목록에 없다. 없어도 프로필 검사는 통과한다. 파일이 있으면 본문을 검사한다 |
| 경로 | `{docs_root}/DEV-25-화면정의서/DEV-25-{슬러그}.md` |
| 위치 | 다건. 루트 단독 파일은 DOC_PATH |
| 제목 | `#` 줄에 `DEV-25`가 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-25. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸의 `…`와 헤더의 `YYYY-MM-DD`는 실패한다. `없음`과 `미결`은 자리표시가 아니다 |
| 빈 칸 | `비고`가 아니고 `□`를 포함하지 않는 헤더의 빈 칸은 모든 표에서 EMPTY_CELL. `□ 시안`의 헤더는 `종류`·`링크`라 이 예외에 해당하지 않는다 |
| 선택 절 | ○ 흐름은 string이라 열 검사가 없다. ○ 관련 문서의 열도 검사하지 않는다. 복사용 관련 문서 열은 코드·경로 |
| 미결 | 스키마 열은 ID·내용. 열 이름은 검사하지 않는다. 빈칸은 EMPTY_CELL이라 `미결`과 다음에 할 일을 내용 칸에 적는다 |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 화면 목적 | string, min 1 | 자리표시가 아닌 1자 이상 |
| ＊ 진입·이탈 | table. 구분, 경로. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 주요 UI 요소 | table. 요소, 동작. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 상태 | table. 상태, 사용자에게 보이는 것. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |

흐름을 그릴 때의 모양이다. 노드 이름 `가칭`은 제품 화면이 아니다.

```mermaid
flowchart LR
  가칭진입 --> 가칭이화면
  가칭이화면 --> 가칭이탈
```

한 파일만 볼 때: `python _tools/docs_lint.py {docs_root} --only DEV-25 --skip-schema-sync --summary-only`

## 복사한 뒤

화면 목적, 진입·이탈의 경로, UI 요소, 상태의 `사용자에게 보이는 것`에 `…`가 남아 있으면 lint가 실패한다. 상태 이름 `로딩`·`빈 화면`·`오류`는 예시라 제품에 없으면 그 행을 지운다. 남은 상태 행은 최소 1개이고, 보이는 것 칸은 `…`가 아니어야 한다. 흐름·시안·관련 문서는 내용을 모르면 절을 지운다. 선택 표의 `…`는 FAKEFILL 대상이 아니다.
