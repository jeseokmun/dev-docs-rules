## 문서 성숙도

| 단계 | 이 유형에서 |
|---|---|
| draft | ＊ 대상 기능, ＊ 인수 조건, ＊ 통과 / 실패가 lint를 통과하면 된다 |
| 모르는 값 | 통과 조건을 지어 넣지 않는다. 칸은 `미결`, 미결 표의 `다음에 할 일`에 확인 방법 |
| 리뷰 | 보강 요청은 빠지거나 애매한 AC의 목록이다 |
| active | 핵심 미결이 닫히고, 검증 칸의 절차로 통과와 실패를 가를 수 있을 때 |
| 어긋남 | 테스트나 제품 동작이 조건과 다르면 조건을 고친다 |
| 어긋남 | 고치지 못하면 상태를 deprecated로 둔다 |

## 사람 검토

항목 이름은 복사용 본문의 제목과 같다.

| 항목 | 사람이 볼 것 |
|---|---|
| ＊ 대상 기능 | 어느 기능인지를 구분 칸에 적는다. 이 절은 kv_rows가 아니라 table이라 구분 칸의 문자는 스키마 키 목록에 묶이지 않는다. 복사용 `기능`은 양식이 제안하는 행 이름이고, 추적 단위가 다르면 그 칸만 바꾼다. Therese Fessenden의 Aesthetic and Minimalist Design(2021-01-24, Nielsen heuristic 8)는 그 칸의 일과 상관없는 정보를 두지 말라고 한다. 기능 행은 어느 기능인지만 적고, 다른 요구의 계산은 그 칸에 두지 않는다 |
| ＊ 대상 기능 | 요구 문서의 어느 항목인지를 구분 칸에 적는다. 복사용 `DEV-20 항목`은 양식이 제안하는 행 이름이다. Google developer documentation style guide의 Cross-references and linking은 설명을 구체적으로 적되, 링크가 이미 말한 문구를 옆에 다시 쓰지 말라고 한다. 헤더 범위가 요구 번호를 가리키면 그 요구의 문구를 괄호로 붙이지 않는다 |
| ＊ 인수 조건 | 조건 칸은 통과와 실패가 갈리는 관찰 가능한 상태만 적는다. ID는 이 파일 안에서 다시 가리킬 수 있게 붙인다 |
| ＊ 인수 조건 | 검증 칸은 그 조건을 보는 절차만 적는다. 문구 키는 그 칸에 두지 않고 DEV-28에 둔다. Martin Fowler의 Page Object(2013-09-10)는 테스트가 의도를 말하고 화면 위젯의 세부는 숨기라고 한다. Raluca Budiu의 Memory Recognition and Recall in User Interfaces(2024-01-15, Nielsen heuristic 6)는 고를 대상을 그 칸에 보이라고 한다. 조건이 문서를 둘 이상 가리키면 검증 칸은 그 확인이 보는 id를 적는다 |
| ＊ 통과 / 실패 | 통과는 위 AC 전항 충족이다. 복사용 두 행은 이 양식의 기본 판정이다. 제품의 판정이 다르면 그 문장을 바꾼다 |
| ＊ 통과 / 실패 | 실패는 어느 AC라도 불충족이다 |
| ○ 관련 문서 | DEV-20 요구와 DEV-65 테스트처럼 이 조건이 기대는 파일의 코드와 실제 경로. 없으면 행을 넣지 않는다 |

슬러그 예는 `습관체크`, `로그인`처럼 기능 이름이다. 예시는 파일명 모양이고 제품 목록이 아니다.

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준은 `_schemas/DEV-22.schema.json`, `_tools/docs_lint.py`, `_schemas/README.md`이다.

| 항목 | 기준 |
|---|---|
| 역할 | light·full 필수 목록에 없다. 폴더가 없어도 프로필 검사는 통과한다. 파일이 있으면 본문을 검사한다 |
| 경로 | `{docs_root}/DEV-22-인수조건명세서/DEV-22-{슬러그}.md` |
| 위치 | 다건. 루트에 단독 파일이면 DOC_PATH. `archive/`와 `_`로 시작하는 디렉터리는 경로 검사에서 빠진다 |
| 제목 | `#` 줄에 `DEV-22`가 단어로 있다 |
| 헤더 | 상태·코드·마지막 갱신·범위·비범위. 코드는 DEV-22. 날짜는 달력의 YYYY-MM-DD |
| 상태 | 기본 draft, active, deprecated. DOC-CONFIG `statuses`가 있으면 그 목록 |
| 자리표시 | 필수 칸의 `…`와 헤더의 `YYYY-MM-DD`는 실패한다. `없음`과 `미결`은 자리표시가 아니다 |
| 빈 칸 | `비고`·`□` 헤더가 아닌 빈 칸은 모든 표에서 EMPTY_CELL |
| 선택 절 | ○ 관련 문서의 열은 검사하지 않는다. 복사용 열은 코드·경로 |
| 미결 | 스키마 열은 ID·미결·다음에 할 일. 열 이름은 검사하지 않는다. 세 칸 모두 비우면 EMPTY_CELL이다. `미결` 칸에 글자 `미결`을 두고 `다음에 할 일`에 확인 행동을 적는다 |

| 필수 제목 | 스키마 | lint |
|---|---|---|
| ＊ 대상 기능 | table. 구분, 내용. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 인수 조건 | table. ID, 조건, 검증. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |
| ＊ 통과 / 실패 | table. 결과, 기준. min_rows 1 | 열 순서, 1행 이상, 빈 칸, 자리표시 |

## 복사한 뒤

대상 기능과 인수 조건의 `…`는 바꾸기 전에 lint가 실패한다. AC가 둘 이상이면 행을 더한다. 통과·실패 문장은 기본 판정이라 `…`가 아니다. 제품이 그 판정을 쓰지 않으면 기준 칸을 고친 뒤에 통과로 본다. 관련 문서의 파일이 없으면 그 행을 만들지 않는다. 경로를 모르면 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 시작한다. DEV-65 행은 테스트 명세가 이 조건을 검사할 때만 추가한다.
