# 템플릿 — DEV-60 운영절차서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「반복 운영 절차」. 파일 하나 = 반복해서 하는 절차 하나.
> **경로:** `{docs_root}/DEV-60-운영절차서/DEV-60-{슬러그}.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 이 절차가 끝나면 무엇이 되어 있나 | ＊ 목적 | 릴리즈의 사용자 영향은 DEV-90 |
| 언제 이 절차를 시작하는가 | ○ 시작 신호 | 시작 전에 갖춰야 하는 것은 ＊ 사전 조건. 두 표를 한 표로 섞지 않는다 |
| 시작 전에 무엇이 있나 | ＊ 사전 조건 | 배포 환경과 롤백은 DEV-80 |
| 이 차례를 끝내지 못하면 | ○ 에스컬레이션 | 사람 이름과 채널 값을 모르면 미정이라고 적는다. 지난 사례는 DEV-62 |
| 누가 어떤 순서로 하고 무엇을 보면 되나 | ＊ 절차 | 지난 장애의 사례는 DEV-62. 재발 방지가 이 절차를 바꾸면 절차를 고치고 사례의 재발방지 칸에 이 파일 경로를 적는다 |
| 실패하면 로그 어디를 보고 어디까지 되돌리나 | ＊ 실패 시 | 스키마 이전이 실패했을 때의 되돌림은 DEV-38 |
| 저장본을 만들거나 그 저장본을 되돌리나 | 이 유형의 파일 하나 | DEV-38의 롤백이 아니다. 저장본이 없으면 목적에 그 사실을 적고 복사 경로를 짓지 않는다 |
| 권한의 이름과 용도 | ○ 필요 권한 | 비밀 값은 DEV-55 금지 대상이다 |

필수 프로필에 이 코드는 없다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 절이 lint를 통과. ＊ 절차는 1행이면 기계는 통과한다 |
| 리뷰 | 행위자를 모르면 그 칸에 미정을 문장으로 적는다 |
| 리뷰 | 로그 위치를 모르면 그 칸에 미정을 문장으로 적는다. 없는 경로는 짓지 않는다 |
| 리뷰 | 정할 사람은 미결에 적는다 |
| active | 절차를 쓰지 않은 사람이 검증 칸만 보고 성공과 실패를 구분할 수 있다 |
| active | 롤백 칸은 시험 환경에서 한 번 따라가 본 절차다. 따라가 보지 않았으면 active로 두지 않는다 |
| deprecated | 절차를 빼면 이 파일을 deprecated로 둔다 |
| deprecated | 대체 절차 파일의 경로는 미결이 아닌 본문에 남긴다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 목적 | 문자열. 끝나면 성립해 있는 상태를 한 문장으로 적는다. `…` 전체는 `EMPTY_SECTION`이다. `미결` 한 단어는 기계가 통과시키는 假채움이다. |
| ○ 시작 신호 | 신호는 이 절차를 꺼내는 조건이다. 열 `신호`·`시작하면`·`시작하지 않으면`. 사전 조건의 권한·도구와 같은 행에 넣지 않는다. Google SRE 온콜 문서는 경보마다 playbook 항목이 있고, 사람이 바로 행동할 수 없는 경보는 만들지 않는다고 한다. 원인 분석은 이 절차의 첫 행이 아니다 |
| ○ 시작 신호 | 시작하면만 적는다 |
| ○ 시작 신호 | 시작하지 않으면만 적는다 |
| ＊ 사전 조건 | 구분은 자유 글이다. 열 `구분`·`내용`, 최소 1행. 권한, 도구, 선행 절차처럼 시작 전에 필요한 것을 나눈다 |
| ＊ 사전 조건 | 모르면 내용에 미정이라고 적는다 |
| ＊ 사전 조건 | 그 대상은 미정 다음의 문장으로 적는다 |
| ○ 에스컬레이션 | 열 `막을 수 없는 증상`·`넘길 곳`·`넘기지 않음` |
| ○ 에스컬레이션 | 넘길 곳을 모르면 미정이라고 적는다 |
| ○ 에스컬레이션 | 이름 값은 채우지 않는다 |
| ○ 에스컬레이션 | 채널 값은 채우지 않는다 |
| ○ 에스컬레이션 | 넘기지 않음에는 그 호출에 보내지 않을 것만 적는다. 예를 들면 비밀 값이다 |
| ○ 인수 | 이미 한 일만 적는다 |
| ○ 인수 | 넘길 때 받는 사람이 이어받을 메모다. 열은 `이미 한 일`·`지금 상태`·`다음에 할 일` |
| ○ 인수 | 누구인지는 ○ 에스컬레이션이다 |
| ○ 인수 | 사람 이름을 모르면 짓지 않는다 |
| ○ 인수 | 비밀 값을 모르면 짓지 않는다. RFC 8941(M. Nottingham, P-H. Kamp, 2021) 3.1.2는 값과 매개변수를 나눈다. 이미 한 일 칸에 이름이나 비밀을 붙이지 않는다 |
| ○ 인수 | 지금 상태만 적는다 |
| ○ 인수 | 다음에 할 일만 적는다 |
| ＊ 절차 | 행동은 그 차례의 조작만 적는다. 열 `순서`·`행위자`·`행동`·`검증`, 최소 1행. 순서는 하는 차례, 행위자는 사람 또는 역할이다. 행위자를 모르면 미정이라고 적는다 |
| ＊ 절차 | 검증은 그 차례가 됐는지 보는 결과만 적는다. 사용자가 파일을 설치하는 절차는 DEV-10이고, 그 문장을 검증 칸에 다시 쓰지 않는다. active 전에는 검증이 '확인' 한 단어가 아니어야 한다 |
| ＊ 실패 시 | 증상은 보이는 실패다. 열 `증상`·`로그`·`롤백`, 최소 1행 |
| ＊ 실패 시 | 로그는 볼 위치다. 로그 원문 안의 비밀은 붙이지 않는다. 로그 칸은 되돌린 다음의 위치다 |
| ＊ 실패 시 | 롤백 칸은 먼저 되돌리는 일이다. 되돌릴 수 없으면 롤백 칸에 되돌리지 못하는 범위를 적는다. Google SRE 긴급 대응은 시험하지 않은 되돌림이 장애를 길게 만든다고 적는다. 롤백을 시험 환경에서 따라가 보지 않았으면 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 그 시험을 적는다 |
| ○ 필요 권한 | 권한은 이름이다. 열 `권한`·`용도`. 값을 적지 않는다 |
| ○ 필요 권한 | 용도는 그 절차에서 쓰는 이유다. 사전 조건의 권한 행과 같은 사실이면 한쪽에 적고 다른 칸은 그 행을 가리킨다 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-60.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-60-운영절차서/DEV-60-{슬러그}.md` |
| 위치 | 다건. 폴더 밖 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-60`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-60`이 단어로 있다 |

| 필수 제목 | 형태 | 최소 |
|---|---|---|
| ＊ 목적 | 문자열 | 자리표시가 아닌 1자 |
| ＊ 사전 조건 | 구분, 내용 | 1행 |
| ＊ 절차 | 순서, 행위자, 행동, 검증 | 1행 |
| ＊ 실패 시 | 증상, 로그, 롤백 | 1행 |

필수 칸이나 필수 문자열 전체의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL` 또는 `EMPTY_SECTION`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. 선택 표의 `…`는 `FAKEFILL`이 아니다. 빈 칸은 `EMPTY_CELL`이다. 필수 열에 `비고`·`□` 예외는 없다. 미결 열은 `ID`·`미결`·`다음에 할 일`이다. 스키마 `rules`는 실행되지 않는다.

## 작성 규칙

- 범위는 이 반복 절차, 비범위는 배포·롤백(DEV-80)과 지난 사례(DEV-62)다.
- 슬러그는 lint가 검사하지 않는다. 절차 이름이면 충분하다.
- 절차 행을 늘리는 것은 실제 차례가 있을 때다. 빈 차례를 채우려고 행을 추가하지 않는다.
- 비밀 값과 개인정보 샘플은 넣지 않는다.
