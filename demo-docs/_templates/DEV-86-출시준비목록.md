# 템플릿 — DEV-86 출시준비목록 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「이번 출시를 막는 문」. 제품당 파일 하나. Google SRE 책의 Launch Coordination Checklist(2005년 무렵)는 출시 자격을 보는 문이고, 배포 절차나 변경 목록이 아니다.
> **경로:** `{docs_root}/DEV-86-출시준비목록.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다. 사람 수, 비율, 점수를 지어 넣지 않는다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 이번 출시를 이 문이 막나 | ＊ 문 | 배포 순서와 롤백 방법은 DEV-80. 사용자가 보는 변경은 DEV-90. 스토어 문구와 제출 여부는 DEV-85 |
| 시험이 무엇을 통과로 보나 | 적지 않는다 | DEV-65·DEV-22. 통과했다고 이 표에 베끼지 않는다 |
| 알고 있는 위험과 갚는 조건 | 적지 않는다 | DEV-64. 위험 행을 문으로 옮겨 두 벌로 두지 않는다 |

필수 프로필에 이 코드는 없다. 파일이 없으면 본문 검사를 하지 않는다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | ＊ 문이 1행 이상이다 |
| draft | lint를 통과한다 |
| 리뷰 | 각 근거가 다른 문서의 경로이거나 비어 있는 id인지 본다 |
| 리뷰 | 근거 없이 `막지 않음`이 있으면 그 행을 고친다 |
| active | `모름`과 `막음`이 없다 |
| active | 각 `막지 않음`의 근거 파일이 그 문을 닫은 문장을 가지고 있다 |
| deprecated | 출시 대상이 바뀌면 이 파일을 기록으로 남긴다 |
| deprecated | 상태는 deprecated로 둔다 |
| deprecated | 문 행을 지우지 않는다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 문 | 문은 예/아니오로 답할 질문이다. 열 `문`·`근거`·`판정`, 최소 1행 |
| ＊ 문 | 근거가 경로이면 그 파일의 경로만 적는다. 없는 경로는 짓지 않는다 |
| ＊ 문 | 근거가 비어 있는 id이면 그 id만 적는다 |
| ＊ 문 | 그 문서의 문장을 이 칸에 다시 쓰지 않는다 |
| ＊ 문 | 판정은 `막음`, `막지 않음`, `모름`만이다 |
| ＊ 문 | 근거가 없으면 `모름`이다 |
| ＊ 문 | `막지 않음`으로 빈 근거를 가리지 않는다 |
| ○ 관련 문서 | 열 `코드`·`경로`. 있는 파일만. |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-86.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-86-출시준비목록.md` |
| 위치 | 단건. 폴더 안 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-86`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-86`이 단어로 있다 |
| ＊ 문 | 열 `문`, `근거`, `판정`. 최소 1행. `판정`이 세 단어 밖이면 `COLUMN_VALUE` |

미결 열은 `ID`·`미결`·`다음에 할 일`이다. lint는 그 열 이름을 보지 않는다. 스키마 `rules`는 실행되지 않는다. 선택 표의 `…`는 `FAKEFILL`이 아니고 빈 칸은 `EMPTY_CELL`이다.

## 작성 규칙

- 한 행은 문 하나다. 배포 명령과 변경 목록을 같은 칸에 적지 않는다.
- `모름`인 행은 미결에 다음에 볼 파일을 적는다. 해시, 사람 수, 비율을 지어 `막지 않음`으로 바꾸지 않는다.
