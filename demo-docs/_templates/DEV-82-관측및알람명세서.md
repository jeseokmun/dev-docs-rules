# 템플릿 — DEV-82 관측및알람명세서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「메트릭·알람」. 파일 하나 = 서비스 또는 영역 하나.
> **경로:** `{docs_root}/DEV-82-관측및알람명세서/DEV-82-{슬러그}.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다. 이 패키지는 원격 수집 제품을 정하지 않는다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 무엇을 보고, 어떤 값에서, 누구에게, 무엇을 하나 | ＊ 관측 | 배포 순서와 롤백은 DEV-80. 대응 칸에는 그 파일의 단계 번호를 적을 수 있다. 로그에 넣지 않을 데이터는 DEV-55 |
| 화면이 어디인가 | ○ 대시보드 | 없는 URL을 만들지 않는다 |
| 화면이 어디인가 | ○ 대시보드 | 주소를 모르면 그 절의 자리표시 행은 두지 않는다 |
| 화면이 어디인가 | ○ 대시보드 | 미결 칸은 `없는 사실:`으로 시작한다 |
| 화면이 어디인가 | ○ 대시보드 | 다음에 할 일 칸은 `다음 행동:`으로 시작한다 |
| 신호가 기기 밖 제품으로 가나 | 신호 칸에 나가는 종류만 | 제품 이름·데이터·중단 시는 DEV-48. 개인정보이면 DEV-58을 먼저 고친 뒤에 제품 이름을 적는다 |

필수 프로필에 이 코드는 없다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | ＊ 관측 1행이 lint를 통과 |
| 리뷰 | 임계 숫자를 재지 않았으면 숫자를 넣지 않는다 |
| 리뷰 | 재는 절차는 미결에 적는다 |
| active | 각 신호의 임계가 코드·대시보드의 값이거나, 원격 임계가 없다는 확인된 문장이다 |
| active | 알림 대상이 있으면 그 대상의 이름만 적고 주소·키는 적지 않는다 |
| deprecated | 신호를 빼면 행을 지우기보다 대응 칸에 폐기라고 적는다 |
| deprecated | 대체 신호는 그 폐기 문장과 따로 적는다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 관측 | 신호는 지표의 이름이다 |
| ＊ 관측 | 열은 `신호`·`임계`·`알림`·`대응`이고 최소 1행이다 |
| ＊ 관측 | 신호는 지표의 의미다 |
| ＊ 관측 | 임계는 조건이다. Prometheus alerting rules는 조건인 expr과 설명인 annotations를 나눈다 |
| ＊ 관측 | 숫자를 지어 넣지 않는다 |
| ＊ 관측 | 임계를 정할 계획만 있으면 `임계 미정`이라고 적는다 |
| ＊ 관측 | 정할 행동은 미결에 적는다 |
| ＊ 관측 | 원격 수집이 없으면 임계에 `원격 임계 없음`이라고 적는다 |
| ＊ 관측 | 임계는 심각도다 |
| ＊ 관측 | 알림은 받는 곳이다. OWASP Logging Cheat Sheet는 기록 위치(Where to record event data)와 빼야 할 데이터(Data to exclude)를 나눈다. 알림 칸에 빼야 할 데이터 규칙을 다시 쓰지 않고 DEV-55를 가리킨다. 원격 수집이 없으면 알림에 `알림 채널 없음`이라고 적는다 |
| ＊ 관측 | 대응은 처음 하는 일이다. 원격 수집이 없으면 그 사실을 코드에서 본 범위를 대응 또는 미결에 적는다 |
| ○ 대시보드 | 이름만 적는다. 열 `이름`·`링크`·`비고`. `이름`의 `…`는 선택 표라 `FAKEFILL`은 아니나 사람 검토는 假채움으로 본다 |
| ○ 대시보드 | 링크는 있는 주소다. `링크`의 `…`는 선택 표라 `FAKEFILL`은 아니나 사람 검토는 假채움으로 본다 |
| ○ 대시보드 | `비고` 헤더라 그 칸의 빈 값과 `…`는 lint를 통과한다 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-82.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-82-관측및알람명세서/DEV-82-{슬러그}.md` |
| 위치 | 다건. 폴더 밖 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-82`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-82`가 단어로 있다 |

| 필수 제목 | 열 순서 | 최소 행 |
|---|---|---|
| ＊ 관측 | 신호, 임계, 알림, 대응 | 1 |

필수 칸의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. 필수 열에 `비고`·`□` 예외는 없다. 미결 열은 `ID`·`미결`·`다음에 할 일`이다. 스키마 `rules`는 실행되지 않는다. `SECRET_LIKE`는 웹훅 URL의 비밀 조각을 놓칠 수 있다. 헌법 §1 원칙 5대로 키와 토큰은 넣지 않는다.

## 작성 규칙

- 헤더 범위는 이 영역에서 보는 신호, 헤더 비범위는 외부 제품 계약(DEV-48)과 배포 절차(DEV-80)의 전문이다.
- 슬러그는 lint가 검사하지 않는다. 서비스나 영역 이름이면 충분하다. lint는 슬러그와 제목을 비교하지 않는다.
- 대시보드 주소를 모르면 ○ 대시보드의 자리표시 행은 두지 않는다. 미결 칸은 `없는 사실:`으로 시작하고, 다음에 할 일 칸은 `다음 행동:`으로 시작한다. `…`를 남기지 않는다.
