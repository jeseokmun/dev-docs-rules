# 템플릿 — DEV-55 보안명세서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「인증·인가·신뢰 경계」. 제품당 파일 하나.
> **경로:** `{docs_root}/DEV-55-보안명세서.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 경계의 안과 밖 | ＊ 신뢰 경계 | 모듈 의존 그림은 DEV-30. 여기에는 그 파일의 경로를 링크한다 |
| 누가 어떤 자격으로 들어오나 | ＊ 인증·인가 | 설정 키 이름만 필요하면 DEV-45 |
| 민감 데이터를 어디에 두나 | ＊ 민감 데이터 | 개인정보의 수집·보관·동의·삭제는 DEV-58. 같은 표를 복붙하지 않는다. 헌법 §1 원칙 2 |
| 하지 않는 통제 | ＊ 하지 않는 것 | 위협 목록을 만들지 않았으면 ○ 위협과 대응 절을 빼는 편이 빈 위협 행보다 낫다 |
| 문서에 올리지 않을 비밀 | ＊ 비밀 금지 | 외부 제품의 계약은 DEV-48 |

필수 프로필에 이 코드는 없다. 파일이 없으면 본문 검사를 하지 않는다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 다섯 절이 lint를 통과 |
| 리뷰 | 모르는 경계·역할은 미결의 다음 행동으로 남긴다 |
| active | 각 경계 행을 DEV-30 또는 코드에서 다시 찾을 수 있고, 비밀 금지의 확인 칸이 이 파일을 어떻게 봤는지 적는다 |
| deprecated | 인증 방식이 바뀌면 이 파일을 고치거나 deprecated로 두고 새 설명을 쓴다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 신뢰 경계 | 열 `경계`·`안쪽`·`바깥`, 최소 1행. 세 칸은 서로 다른 사실이다. 안쪽과 바깥에 같은 문장을 반복하지 않는다. |
| ＊ 인증·인가 | 열 `방식`·`역할`·`비고`, 최소 1행. 인증이 없으면 방식에 그 사실을, 비고에 없는 이유를 적는다. 헤더가 정확히 `비고`라 빈 칸과 자리표시는 lint를 통과한다. 사람 검토는 빈 비고를 이유가 빠진 행으로 돌려보낸다. |
| ＊ 민감 데이터 | 열 `종류`·`취급`·`저장`, 최소 1행. 종류는 데이터 이름, 저장은 장소다. 샘플 값과 비밀은 적지 않는다. |
| ＊ 하지 않는 것 | 열 `하지 않음`·`이유`, 최소 1행. 이유는 그 통제를 뺀 결정이다. '범위 밖'만 반복하지 않는다. |
| ＊ 비밀 금지 | 열 `금지`·`확인`, 최소 1행. 금지는 문서와 로그에 두지 않을 종류, 확인은 이번 파일에서 그 종류를 어떻게 봤는지다. |
| ○ 위협과 대응 | 열 `위협`·`대응`·`잔여`. 위협 모델을 쓰기 전에 일반적인 위협 이름을 채우지 않는다. 절을 뺀다. |
| ○ 관련 문서 | 열 `코드`·`경로`. 있는 파일만. DEV-58이 없으면 미결에 다음에 쓸 사람이 적힌다. |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-55.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-55-보안명세서.md` |
| 위치 | 단건. 폴더 안 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-55`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-55`가 단어로 있다 |

| 필수 제목 | 열 순서 | 최소 행 |
|---|---|---|
| ＊ 신뢰 경계 | 경계, 안쪽, 바깥 | 1 |
| ＊ 인증·인가 | 방식, 역할, 비고 | 1 |
| ＊ 민감 데이터 | 종류, 취급, 저장 | 1 |
| ＊ 하지 않는 것 | 하지 않음, 이유 | 1 |
| ＊ 비밀 금지 | 금지, 확인 | 1 |

`비고` 헤더만 자리표시·빈 칸 예외다. 다른 필수 칸의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. 선택 표의 `…`는 `FAKEFILL`이 아니다. 스키마 `rules`는 실행되지 않는다. 미결 열은 `ID`·`미결`·`다음에 할 일`이며 lint는 열 이름을 보지 않는다.

`SECRET_LIKE`는 할당형 비밀, `sk-` 토큰, `Bearer` 토큰, PEM 개인키 헤더만 실패시킨다. 헌법 §1 원칙 5는 키·토큰·비밀번호·개인 실데이터를 모두 금지한다.

## 작성 규칙

- 범위는 이 제품의 신뢰 경계, 비범위는 DEV-58에 맡기는 수집·동의·삭제다.
- 인증이 없는 제품이면 방식 칸에 그 사실을 적는다. 업계의 인증 방식을 채워 넣지 않는다.
- ○ 위협과 대응의 `…`를 남기면 사람 검토가 假채움으로 본다. 위협을 아직 쓰지 않았으면 그 절을 지운다.
- 실자격증명은 넣지 않는다.
