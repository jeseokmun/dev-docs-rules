# 템플릿 — DEV-68 성능목표명세서 (v2.1)

> **v1 기준본 양식.** 고칠 때는 이 파일과 헌법 §0을 함께 본다.
> **용도:** 헌법 §5의 「성능·용량 목표」. 제품당 파일 하나.
> **경로:** `{docs_root}/DEV-68-성능목표명세서.md`
> **가독성:** 표 우선. 산문은 이 양식의 규칙만.

이 유형은 `_tools/docs_draft_cli.py`의 생성 대상이 아니다. 초안은 아래 펜스를 복사한 뒤 칸을 바꾼다.

## 표기

| 기호 | 의미 |
|---|---|
| ＊ | 필수. 스키마 `required` |
| ○ | 권장. 스키마 `optional` |
| □ | 선택 표기. 이 유형 스키마에는 □ 절이 없다 |

## 이 문서와 이웃

| 질문 | 적는 곳 | 적지 않는 곳 |
|---|---|---|
| 어떤 지표를 어떤 목표로, 어떻게 다시 재나 | ＊ 목표 지표 | 그 측정을 자동화한 테스트의 위치는 DEV-65 |
| 재지 않는 것 | ＊ 비목표 | 제품이 만들지 않는 기능은 DEV-20 |
| 부하를 무엇으로 가정하나 | ○ 부하 가정 | 가정을 목표 칸의 실측처럼 적지 않는다 |

필수 프로필에 이 코드는 없다. 이 패키지는 성능 숫자를 정해 두지 않는다.

## 문서 성숙도

| 상태 | 이 유형에서 |
|---|---|
| draft | 필수 두 절이 lint를 통과. 숫자를 아직 정하지 않았으면 목표 칸에 그 사실을 문장으로 적는다 |
| 리뷰 | 재지 않은 지표는 미결에 돌릴 절차를 적는다 |
| 리뷰 | 다음 행동은 그 절차와 다른 문장으로 적는다 |
| active | 목표 칸의 숫자는 측정 칸의 절차로 한 번 이상 나온 값이거나, 숫자 없이 목표만 합의된 문장이다 |
| active | 재지 않은 숫자는 목표 칸에 두지 않는다 |
| deprecated | 지표를 빼면 비목표의 `안 잼` 칸으로 옮긴다 |
| deprecated | 이유는 그 칸과 다른 문장으로 적는다 |

이 저장소에는 유형별 이상형 체크리스트 파일이 없다. `_tools/ideal_check_min.py`는 DEV-10·DEV-30만 본다. 사람 검토를 못 채운 것은 헌법 §1.5.5대로 draft 실패가 아니다.

## 사람 검토

스키마 label은 복사용 H2로 한 번만 있다.

| 항목 | 칸에 쓸 내용 |
|---|---|
| ＊ 목표 지표 | 열 `지표`·`목표`·`측정`, 최소 1행. 지표는 재는 이름, 목표는 숫자와 단위 또는 숫자를 아직 정하지 않았다는 문장, 측정은 다른 사람이 다시 하는 절차다. 절차를 아직 돌리지 않았으면 측정 칸에 그 사실을 적는다. Tom Gilb의 Planguage(Overload 13(70), 2005-12)는 Scale, Meter, Goal을 나눈다. 목표 칸은 앞으로의 수준만 적고, 재는 방법과 아직 재지 않았다는 말은 측정 칸이나 미결에 둔다. |
| ＊ 비목표 | 열 `안 잼`·`이유`, 최소 1행. 이유는 그 지표를 빼는 결정이다. '나중에'만 적지 않는다. |
| ○ 품질 시나리오 | 종류는 `사용` 또는 `변경`만이다. 열 `종류`·`원천`·`자극`·`반응`·`측정`. arc42 10번의 사용 시나리오와 변경 시나리오다 |
| ○ 품질 시나리오 | 원천만 적는다 |
| ○ 품질 시나리오 | 자극만 적는다 |
| ○ 품질 시나리오 | 반응만 적는다 |
| ○ 품질 시나리오 | 측정 칸은 ＊ 목표 지표의 행을 가리킨다 |
| ○ 품질 시나리오 | 그 목표 칸의 초·ms·밀리초·%·건·MB·KB 숫자를 측정 칸에 다시 적으면 `GOAL_COPY`다 |
| ○ 놓쳤을 때 | 놓친 목표는 ＊ 목표 지표의 행을 가리킨다. 열은 `놓친 목표`·`멈출 일`·`계속할 일`. 그 숫자를 다시 적지 않는다 |
| ○ 놓쳤을 때 | 멈출 일은 그때 멈추는 일만 적는다. Google SRE의 오류 예산이 떨어졌을 때 기능을 멈추는 정책에 해당한다. 실측 전에는 이 칸을 정하지 않는다 |
| ○ 놓쳤을 때 | 계속할 일은 그때 계속하는 일만 적는다. 실측 전에는 이 칸을 정하지 않는다 |
| ○ 부하 가정 | 가정만 적는다. 열 `가정`·`값`·`사실/추측`. ISO/IEC 25010의 Performance efficiency(iso25000.com)는 시간 동작, 자원 이용, 용량이다. 보관 기간은 부하가 아니므로 이 표에 두지 않는다. 보관은 DEV-35다 |
| ○ 부하 가정 | 값은 그 가정의 값만 적는다 |
| ○ 부하 가정 | 사실/추측은 값을 관측했으면 `사실`과 출처를 적는다. 짐작이면 헌법 §1 원칙 4대로 그 칸을 `추측:`으로 시작한다. lint는 이 접두사를 보지 않는다 |

헌법 §1 원칙 2대로 같은 사실을 복붙하지 않는다. 반복되는 사실은 `_schemas/fact-owners.json`의 id를 쓴다. 주인 문서가 그 사실을 한 번 적고, 다른 문서는 id와 경로만 인용한다. 값이 없는 id `HC-REPO`, `HC-DRIFT-VER`, `HC-HASH`, `HC-PKG`, `HC-LEGAL`, `HC-CHANNEL`은 비워 둔다. `HC-STREAK`의 주인은 DEV-30, `HC-DRIFT-STATE`의 주인은 DEV-50, `HC-FLAG`의 주인은 DEV-52, `HC-MIDNIGHT`의 주인은 DEV-70, `HC-PLATFORM`의 주인은 DEV-10, `TOOL-PY`의 주인은 `README`, `TOOL-EXIT`의 주인은 `_tools/README.md`이다.

## 기계 검사

기준 파일은 `_schemas/DEV-68.schema.json`과 `_tools/docs_lint.py`다.

| 항목 | 기준 |
|---|---|
| 경로 | `{docs_root}/DEV-68-성능목표명세서.md` |
| 위치 | 단건. 폴더 안 파일은 `DOC_PATH` |
| 헤더 | `상태`·`코드`·`마지막 갱신`·`범위`·`비범위`. 코드는 `DEV-68`. 날짜는 달력의 `YYYY-MM-DD` |
| 제목 | `^#` 줄에 `DEV-68`이 단어로 있다 |

| 필수 제목 | 열 순서 | 최소 행 |
|---|---|---|
| ＊ 목표 지표 | 지표, 목표, 측정 | 1 |
| ＊ 비목표 | 안 잼, 이유 | 1 |

○ 품질 시나리오가 있으면 `종류`가 `사용`·`변경` 밖이면 `COLUMN_VALUE`다. 열 순서가 다르면 `TABLE_COLUMNS`다. 측정 칸이 ＊ 목표 지표의 목표 숫자를 다시 적으면 `GOAL_COPY`다.

필수 칸의 `…`, `TBD`, `TODO`, `-`, `—`, `YYYY-MM-DD`는 `FAKEFILL`이다. 판정은 `_tools/docs_common.py`의 `placeholder`다. 선택 표의 `…`는 `FAKEFILL`이 아니다. 짐작한 밀리초를 목표 칸에 숫자로만 적어도 기계는 통과한다. 그 숫자는 사람 검토가 돌려보낸다. 미결 열은 `ID`·`미결`·`다음에 할 일`이다. 스키마 `rules`는 실행되지 않는다.

## 작성 규칙

- 범위는 이 문서가 맡는 지표, 비범위는 테스트 케이스의 절차 전문(DEV-65)이다.
- 목표 칸에 단위 없는 숫자를 두지 않는다. 단위를 모르면 미결에 적는다.
- 측정 절차를 돌리기 전에는 목표 칸을 실측값이라고 부르지 않는다.
